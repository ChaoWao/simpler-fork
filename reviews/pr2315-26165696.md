## 1. 背景与问题

HBG 的 Runtime 同时保存 device 执行字段和 host 编排/lease 状态。#2309 已将上传范围从整个 Runtime 缩到 host_ 之前，节省字节已经交付；这里解决的是类型表达与可检查性。

具体原状：`Runtime::device_image_bytes()` 返回 `offsetof(Runtime, host_)`，device 字段平铺在非 standard-layout 的 Runtime 里。当前已确认范围只要求在此基础上建立显式 device descriptor，不能再次要求同样的字节收益，也不扩大为共享握手或 capture。

## 2. 方法与理由

Runtime 变为首成员 `DeviceRuntimeLaunchDesc dev` 加原有 `HostOnlyState host_`。上传长度由 `sizeof(DeviceRuntimeLaunchDesc)` 决定；descriptor 本身受 standard-layout、trivially-copyable、64-byte 整数倍约束。Runtime 的 offset=0 与 host_ 不重叠断言继续保护既有复制起点。

读写方改为 `runtime->dev.X`，公共 accessor 保持签名；三处 AICPU cache invalidation 与复制长度一致。原来“以 host_ 偏移决定前缀”变成“以被复制类型的大小决定前缀”。不改变每槽 runtime_args、prepare 上传点、握手初始化或准入。

保留 teardown_gates 的既有初始化合同，也保留 tensor_leases 的 const/mutable 接口。Descriptor 表达可见性，不宣称内部字段拥有同样的写入方或生命周期。
