01 / 性能目标

Host 可以忙，设备不应因此等待

稳态每步时间 ≈ 设备关键路径时间

主机为下一次调用做准备时，设备执行当前调用。主机工作赶在设备需要之前完成，未被覆盖的主机等待应小到可以忽略。

HBG：减少设备控制开销

将适合的构图与依赖准备放到主机，让设备主要承担计算和必要调度。新增的主机构图、打包和传输也必须被覆盖。

Async：保持设备持续有工作

重叠准备、提交和安全回收；资源不足时按实际可用资源背压。足够的排队只能吸收波动，不能弥补长期供给不足。

整体验收：证明组合成立

从真实模型与请求入口测量，检查设备空洞、持续补队和主机暴露时间，同时验证数值与资源寿命。

“设备时间”是完成同等有效工作的设备执行关键路径，包含设备调度、必要传输及通信的实际影响；不能只统计忙碌的算子、删掉设备内开销。主机关键路径占比很低，也不代表设备执行本身已经足够快。

H 小于 D，主机准备能被设备执行覆盖；剩余交接等待仍需缩小。

模型公式：可提前准备时，稳态周期 = max(H, D + g)；主机反馈阻塞时 = H + D + g。前者假设有限缓冲足以支撑该流水线、布局已知且无额外资源冲突。首轮启动和最后排空没有被隐藏，仍计入完整请求延迟。

自回归依赖必须真实满足：后继可提前持有设备地址，不等于已经有了数据；仍需正确设备顺序。若采样、分支或动态形状必须由 host 读取前驱结果决定，这段等待仍在关键路径，Async API 本身不会消除它。

同模型、精度、负载与硬件上的实际服务基准。

这里的“<”是工程目标，不是已测结果。等量工作的延迟越低越好；吞吐则越高越好。单请求延迟与服务吞吐分开验证，不用增加 batch 或放宽尾延迟冒充同条件加速。

比较保持一致要回答的问题
HBG vs TMR尽量相同模型、算子实现、精度、输入、KV、服务调度；使用同一 Async 策略设备控制成本节省了多少？host 准备、上传是否吃回收益？不可避免的生成代码差异单独记录。
Async vs 同步对照分别在 HBG/TMR 上保持有效计算不变设备间隙是否缩小，端到端周期是否接近设备周期，资源峰值增加多少？
TMR/HBG vs vLLM-Ascend权重/tokenizer、精度与质量门槛、硬件/并行规模、请求流、输入输出长度、缓存状态完整推理与服务性能是否更好？先做受控 eager 比较，再做各自可部署优化配置比较，明确 graph/capture 差异。

关键路径验收

在持续有有效请求的稳态窗口，按统一时间基准测量设备等 host 的间隙。报告总占比与间隙 P50/P95/P99，区分输入依赖、资源背压和上游供给不足。

整体性能验收

报告设备执行、首 token 延迟、每 token 延迟、请求延迟与有效吞吐；尾延迟、CPU、HBM 和主机内存一起报告。预热与冷启动单列。

明确“可忽略”

建议将“稳态 host 等待占比 ≤ 1%”作为待确定的验收阈值，同时检查尾部间隙。它是本方案的建议，不是已批准的数值承诺或 runtime 参数。

诊断工具用于解释差距，正式性能轮关闭高扰动诊断。重复测量采用交错顺序，报告离散度/置信区间；小于测量噪声的差异不宣布胜出。PMU 尚未可靠时，不引用其计数证明性能，但可用独立校验的计时继续基础验收。

04 / 功能闭环

同一个真实模型，穿过四个仓库

pypto-serving请求调度 · KV · 采样 · 输出
pypto-lib模型结构 · 算子组合
pypto编译 · HBG/TMR 产物
simpler准入 · 提交 · 执行 · 退休

首个完整验收建议复用 Qwen3-14B / A3 基础：prefill → 连续 decode → 多请求持续到达 → 结束回收。从源码生成真实产物，记录实际加载身份；手写示例、私人旧二进制或 CPU prefill 只作定位对照。

数值要贯通

算子组合、单层、全模型逐层核对。相同前缀下比较 logits/KV，再做自由生成；对齐归一化、舍入与精度边界，不用放宽容差掩盖错误。

请求要持续

不同请求拥有独立可变 KV/输出。DEVICE feedback、安全复用、自动准入与背压一起验证；覆盖不同长度、提前结束、部分提交失败和 close。

边界要保留

设备 operator 串行、parent FIFO、最后消费者后退休、有限资源与明确背压；不引入隐式跨 run host 同步。未验证的平台与形态不外推支持。

遇到性能差距，按什么顺序处理？
  1. 设备等待 host：先定位必需反馈、隐藏同步、准备/提交不足和资源回收阻塞，量化各自贡献。
  2. host 已被覆盖，但 HBG 不快：比较设备调度、算子执行、数据移动和图表示成本；降低主机占比已不够。
  3. TMR 仍慢于 vLLM：分别归因算子/融合、内存与 KV、设备调度、服务调度；不能只优化 runtime。
  4. 设备微基准快，服务不快：检查排队、采样、请求组织和输出路径，计入真实用户延迟。
