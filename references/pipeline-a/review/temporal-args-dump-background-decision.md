## 1. 要解决什么

ArgsDump 保存算子参数的实际内容和一份解释这些内容的清单，供离线查看和任务复现。目前虽然已有写文件线程，每个 run 收尾仍要等它写完，再整理清单；开启多 run 后台采集时，这一段仍挡住后继。

本次让 **N 的文件写入与清单整理留在主机后台，N+1 按原有顺序在设备执行**。设备算子仍串行，不增加设备并发。

```text
现在：N 设备完成 → 等参数文件与清单写完 → N 返回 → N+1
改后：N 设备完成 → 有限接收确认和必要的剩余内容拷贝 → N 返回 → N+1
                                      └→ 后台写参数文件、发布清单
```

这次仍保留有限接收确认以及必要的设备到主机复制，并非设备一完成就无条件返回。

## 2. 用户如何使用

- 仅本地 L3、显式 `collect_across_runs=True` 且开启 ArgsDump 时启用。
- `run` 返回表示本次设备调用完成，**不再保证参数文件已写完**。读取文件前调用现有 `flush_diagnostics(timeout)`。
- flush 成功要求：调用前已关闭的每个 run，其参数内容写入和清单发布都完成；缺记录、主机丢弃、写盘失败或完整性不明均报错。
- 默认关闭此选项时保持现有行为和文件布局。不引入“session”接口，不开放 capture/replay、远程 L3 或新的设备执行范围。
- 可与已交付的时间线、编排阶段和 PMU 后台输出组合；一个 collector 失败不能跳过其他 collector 的 flush。

## 3. 谁持有数据，何时能复用

1. 每个 runner 的 ArgsDump collector 继续持有设备池和服务线程；每个 run 独立持有身份、采集等级、文件目标、主机记录和完整性结论。
2. 接收线程将参数内容复制到该 run 拥有的主机内存，再把写入请求交给 writer。writer 不读后继会修改的设备 arena 或共享输出状态。
3. 参数文件的 offset 分配与请求入队必须在同一把锁内完成，保持实际文件追加顺序与清单 offset 一致；入队失败回滚未提交的 offset，或使整个输出失败而不发布错误清单。
4. lane 的 published/completed 计数在 collector 生命周期内累计，避免 N+1 初始化抹掉 N 尚未处理的确认。禁用 ArgsDump 的 run 不重置这些计数；重建池必须先排干并结束旧 writer，再成对初始化。
5. arena 确认表示内容已被安全复制或明确记为丢失，不承诺已写盘。故意丢弃可推进设备确认，但必须令该 run 的 flush 失败；不能伪装成完整采集。

### 剩余 buffer 的判断

只在已观察到本 run 设备完成、仍持有执行权并阻止后继开始时处理。先读取 terminal state，完成有限队列 cut，再用 **本 run、lane、接收序号及有效性**核对交接。循环队列 head/tail 不能作为历史计数；设备地址也不能单独作为 buffer 身份。

先用 terminal state 中的 `current_buf_seq` 与本 run 的接收账本比较：已交接的序号不再读取其已回收 buffer；只有证明尚未交接、映射仍有效时，才读取并校验 buffer 的 epoch/序号/count。未知映射、序号不连续、回绕、copy 失败或 cut 失败均判完整性未知。证明尚未交接的内容必须在释放执行权前将 **metadata 和实际 payload 一起复制**到主机；不能只保留设备指针。映射与 arena 在这段复制结束前不能被收尾释放。

未观察到设备完成时，不新增主动恢复读取；把已经归属该 run 的主机记录标成不完整。**本次放弃这种故障下对未交接 buffer 的额外抢救**，flush 报错。原有普通模式故障诊断不改。

## 4. 背压、内存与文件代价

- 每个 ArgsDump collector 新增独立 **256 MiB 主机保留预算**，最多两个未发布 run。第三个或相同目标仍被占用时，在设备提交前拒绝本次 run。
- 预算覆盖保留的 metadata、payload、队列节点及每 run 固定状态；按实际容器容量计费，扩容期间新旧存储同时计入，先收费再分配，失败释放本次预留。seal 使用原地排序和固定空间流式合并，不另复制一份全部 metadata。
- 运行途中预算/分配失败不能阻塞接收线程等 writer 腾空间：记录丢失、推进安全确认、继续收尾，flush 明确失败。慢盘可能导致 run 准入拒绝或 flush 超时；磁盘阻塞期间不能承诺有界 writer join。
- 256 MiB 是 ArgsDump 的独立额度，**不是全部 DFX 的总额度**；与其他 collector 的占用相加。设备池大小不变。
- 每个输出使用独占的 payload 文件及临时清单，原子替换最终清单；清单通过已有 `bin_file` 指向对应 payload。同目标跨进程发布采用最后一次成功发布生效，文件对不能混杂。
- 已发布 payload 不自动删除，避免旧清单的读者失去内容；失败证据也保留。因此重复输出会积累磁盘文件，需要使用者清理。普通重复 run 没有“16次/17次”限制；16只是相同 epoch 文件名发生碰撞时的尝试上限。
- 增加预算记账、序号核对、文件创建和保留内存；不承诺延迟或吞吐收益。

## 5. 失败与关闭

- 不完整结论持续保留至 runner 销毁；删除磁盘证据不清除该 runner 的已记录错误。原有设备端配置截断继续沿用现有标记，不能与新增主机丢失混为一谈。
- 未经引用释放确认，不得对仍被接收线程写入的 metadata 排序、封存或释放。失败时保留所有权并唤醒等待者；完成 host reader join 后才能处理这些主机记录。
- `Worker.close` 仍先停止准入并排干已有操作/run，执行诊断 flush，再执行既有 teardown。诊断错误保留为关闭结果，不能跳过 teardown；尚未排干的操作/run 仍按现有规则拒绝提前释放。
- fatal 路径的真实顺序是先停止 collector，再尝试 reset。沿用既有 abandon 回调，不执行逐块 device free/unregister；不能把 no-op 回调或 host join 当成设备已经停止的证明。reset 未确认时继续既有保留/隔离，不新增 reset、重试或恢复能力。
- “不新增主动恢复读取”不等于“现有 stop 路径绝不访问设备”：公共 stop 仍可能执行既有最后一轮接收。不得将这轮 best-effort 接收提升为完成证明。writer 仅处理已安全取得所有权的主机副本；所有设备释放依赖原有正常/abandon 分支。
- finalize 只在相关 reader 引用已释放或已 join 后完成主机封存，再停止 writer；未成功发布也必须有终止路径。收尾新发现的 ArgsDump 错误，经 retained 路径的 native finalize 返回值/teardown report 上报，保留原有首个设备错误；不能声称较早执行的 Python pre-flush 会收到后来才发生的错误。

## 6. 一个 PR 的交付与验收

实现覆盖 ArgsDump collector 的 run 归属、writer、预算、计数、封存与失败；公共 runner 的准入/flush/回滚/关闭接线及 a2a3/a5 原生收尾错误传播；文档和针对性新用例。保持默认路径及设备 wire 布局，不借机扩大其他架构。

主要验收：

1. N 的 writer 被阻塞时，N+1 能开始且两者内容/offset/清单不混；第三个未发布 run 在 launch 前被拒绝。
2. 多次 buffer 复用、队列绕圈、seq 0、未交接剩余 buffer、未知/回绕身份的恢复判断；后继开始前已拥有需恢复的 payload。
3. metadata/payload/节点分配失败不额外分配确认节点、不死锁、不静默成功；容器扩容峰值也计入预算。
4. 跨进程命名碰撞、两次发布、读者持有旧清单、写/close/rename 失败，文件对始终一致；零记录 run 的清单明确为空。
5. 设备完成未知、host 引用无法释放、正常与 abandon 收尾，错误可见且不能提前 free；既有错误优先级保持。
6. 关闭选项时原行为保持；与已有三类后台输出组合时，共享 flush 截止时间并汇总错误。
