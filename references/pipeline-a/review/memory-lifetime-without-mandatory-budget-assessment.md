# L2 / L3：寿命管理与可选预算解耦评估

状态：用户要求的静态评估已完成；建议修订旧 L3 合同，不代表实施授权。
基线：`bef53236679a0ff56d38abbf38d5a738f40e530c`，本轮 GitHub main GET 核实一致。未修改源码、运行测试或分派 writer。

## 结论

L2 和 L3 都不以用户配置硬上限为安全前提。建议在受支持的 onboard program 路径默认管理四类工作区的所有权、扩容失败保全和回收；显式额度作为独立可选策略。不要把现有上限简单改成 UINT64_MAX，更不能用预算约束代替最后消费者证明。

旧 L3 “Worker 总额平均分给设备”的方案不继续作为待批准实现：它解决的是额外配额策略，不是跨进程寿命安全必需。保留原文作为历史设计，尚未获实施授权。已交付 L2 的显式预算能力应兼容保留，不能以本次评估为由删除公开配置。

## 为什么不能只删除上限

例：同一region依次需要3、5、7 MiB，各run已正常退休且更大块已发布。现有退休只降引用，make_room_locked在未触及上限时直接返回，历史3和5 MiB可留到关闭。改成巨大上限并不会主动回收它们，也不会在真实设备分配失败后自动扫掉它们。设备可能因可回收的历史块占用而分配失败。

另有host账本：释放成功也保留历史Block条目。无论是否有限预算，长期变化大小的运行都需要历史条目复用/压缩机制；设备字节限额不等于host元数据有界。该项是静态可见的生命周期成本，不是已量测的延迟回归。

## 建议的共同机制

### 1. 管理总是启用，配额可选

仅在明确支持的a2a3/a5 onboard program路径启用；不全局切换kernel/sim/远端等未经审核路径。配置缺省意味着“无用户硬配额”，不是关闭账本。保留已发布L2正数额度语义；内部使用独立的管理状态和可选limit，不把0同时当disabled和unlimited。报告分别表达management可用、budget_enforced和已占用字节；累计计数仍须防溢出。

### 2. 空闲当前块与过时块分开

- 当前region仍发布的块可保留供下一次复用；没有run引用不等于允许另一region拿走它。
- 新计划发布后，被替代的旧块只在最后消费者确实结束时回收。准备失败产生且已无人使用的暂存块也应退出。
- 回收不再等待预算超额。在具备device attach的安全收尾/后续prepare位置处理可回收队列；若此后不再提交run，正常finalize/close也要完成处理。不能在持有任意调用锁的 `drop_ref` 中直接塞进设备free。
- 后端free/unmap失败保留真实所有者和未回收记录，不谎报释放；未知消费者隔离，禁止再次使用该块。当前路径已有runner错误处置必须继续适用，不能靠“无上限”持续接收失败工作。
- 复用/压缩已释放的账本槽，保留累计审计计数与尚未完成的错误记录，检查旧run身份与地址复用不会串账。

首步不必新增通用缓存或人为默认字节上限。保留每region当前容量、回收安全的过时代，是一个可解释的起点；它仍会保留历史最大当前块，并不保证显存随需求变小立即下降。

### 3. 扩容仍需新旧共存

先申请、完成全部准备后才切换；失败保全旧发布计划。没有用户配额后，申请仍可能因设备OOM、host元数据分配失败或地址大小溢出而被拒绝。新旧同时占用是事务保全/在途寿命的成本，不能承诺所有剩余显存都能用于新块。预分配不是本次修订的前提，预热后完全无malloc也不是已有保证。

### 4. L3仍需跨进程关闭证明

子进程复用同一个管理器，不需要父进程平均拆分总预算才能工作。父进程停止准入并排干后，仍需确认子进程最后消费者和异常隔离状态，才能释放可能被借用的父资源。去掉上限不会消除子进程超时/死亡的所有权问题。

旧方案的有期限、新鲜账本查询仍是候选；应从“预算开关”改为“实际受管理消费者/资源”驱动。正常排干关闭，仍有消费者则拒绝释放；停止无法证明时保留资源。不能用child已退出或报告不可读当作设备完成。也不能直接复用L2仅检查live_blocked的代码并宣称覆盖L3隔离风险。

## 实施范围与兼容性评估

这是中等规模的机制调整，不是一行默认值修改。至少涉及：公共Worker配置与说明、ChipWorker能力/latch、WorkspaceManager回收及报告、runner初始化/扩容/最终清理；L3另涉及child初始化、mailbox新鲜查询和父关闭门禁。

建议两个可独立审查的完整交付：
1. L2在现有四区范围内默认安全管理，拆掉预算前置，补齐独立回收与账本复用；已有显式预算仍可用。默认失败保全和错误关闭行为的改变需在合同中列出。
2. L3复用该共同机制并完成跨进程关闭证明；默认不引入父总额均分。若以后确有多租户需求，再明确每设备可选额度，不能改变已发布L2额度的单位。

不建议现在同时重做统一大池、加入全内存覆盖、实现capture/replay或把所有问题藏到新的配置开关后面。未来capture只要求图持有的块有独立长寿命引用，在图引用释放前不可回收；现有run引用本身尚不提供此支持。
