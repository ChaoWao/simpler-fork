# 普通异步：默认按资源自动准入与背压

状态：用户已批准完整合同，一个PR、单提交。实施由#2596交付；当前head、评审及CI状态统一见[进度看板](../run-pipeline-track-a.html)和[经理工作区](../ARCHIVE-INDEX.md#manager-session)。本合同规定功能与验收边界，不保存逐轮CI快照。

## 用户怎么使用

本地 L3 的 A3/A5 × HBG/TMR program，正常创建 Worker 并 submit，无需指定 pipeline_depth、grant 或 launch_depth。设备 operator 仍串行，parent FIFO 不变。

系统复用资源、按需申请新资源，并在资源不能安全复用时背压。请求数准入与设备字节是两种不同约束：前者控制登记和排队，后者由实际工作区分配与消费者寿命决定。没有强制显存预算、设备均分或隐藏的显存比例。

## 一次请求怎样走完

1. **接收。** 父进程在当前准入范围内接收；满了先等待，不提前创建无界的 run 记录。启动容量为1。
2. **准备输入。** HOST 输入已有子进程私有副本；如设备 staging 容量不足，取得本 endpoint 唯一的增长令牌，再申请。DEVICE 输入不因此复制。
3. **构图一次。** 用户编排回调只执行一次，构图结果保留在该请求的主机存储。等待后从原计划继续，不重复调用用户回调。
4. **提交工作区。** 足够的区域直接复用；需扩容时先准备全部新块，全部成功才替换。失败保全原块，并撤销本次未发布的新块及引用。
5. **分配不足。** 先回收确定空闲的缓存，再尝试一次。仍不足且有明确在途消费者时，保存计划并等待这些消费者退休；进度线程继续排干前驱，不在等待中堵住回收者。
6. **恢复或报错。** 只因首次记录的消费者退休而恢复；每个身份只消费一次，不轮询分配。等待集合耗尽仍失败，明确报资源不足。无法证明停止或释放失败时走错误/隔离路径。
7. **上传和排队。** 释放增长令牌；符合现有兼容条件的后继可在前驱完成前入队，设备按序执行。资源在最后消费者结束后复用或回收。
8. **更新容量。** 整个 run 退休时将各 endpoint 的资源证明反馈给父进程，取保守容量。顺序调用反复复用同一套资源；持续存在多个请求时才逐步探索更多套，不按调用次数盲目扩容。

例如：新请求需要40单位，当前只能再分配30单位；前驱占用20单位且有确定退休路径。先等待前驱退休，回收后再申请40；并不因为20小于40而提前拒绝。如果退休后仍申请失败，则报错，不无限等待后来新进入的请求。

## 关闭与失败

关闭先停止新接收，再取消尚未提交设备的等待计划，按其阶段撤销引用、释放令牌和借用；已提交任务沿原关闭路径排干。无设备提交证明时才能释放未执行请求的借用。前驱设备停止未知会使相关等待计划失败，不能将未知资源当空闲。

## 有限资源及代价

- 身份目录采用64 KiB内部表预算，按当前条目布局最多168个执行资源身份；这是实现的有限安全上限，实际准入通常更小。达到目录上限也背压，不宣称无限请求。
- 主机侧增加每请求保存的构图内容、等待身份集合、容量样本，以及前缀扫描和引用登记。等待集合随内部上限有界，精确字节按实现布局核算。
- 同一 endpoint 的增长串行化；扩容时新旧块并存，峰值增加。资源保留也会增加稳态占用。
- 只对四类受管理工作区进行等待/回收判断；event、其他运行时存储和主机分配仍可能直接失败。不是整个设备的显存池，也不保证所有 OOM 都可恢复。
- 每次激活最多两次事务尝试；每阶段最多 D 次激活，两阶段最多4D次事务尝试、8D次底层分配调用。仅真实退休触发恢复，无定时重试。
- 不承诺延迟或吞吐收益。

## 适用边界

仅本地顶层 L3、onboard program 四后端的默认未配置路径。显式深度/预算配置、L2、嵌套 L3、remote/MPI、kernel/borrowed context、sim 保持现行行为。capture/replay 和通信不开放。本地多 endpoint 按整 run 完成反馈合并，不用单设备先完成冒充整体退休。

Qwen driver 已通过 #2592 合入；本 PR 提供资源机制并完成真实 Worker.submit 验收。Qwen 在新机制上的组合验收另记，不把现有可配置深度证据当成自动准入已验证。

## 一个 PR 的验收

- 四后端正常复用、HOST/DEVICE输入寿命、持续补队；新槽零私有字节仍可证明可用。
- 多区域扩容失败保全与事务引用回滚；40/30/20等待案例；多个消费者分别退休、无关退休、容量收缩、等待耗尽。
- 回调只执行一次；单endpoint仅一个增长者；已接收请求在容量下降时保留身份但重新检查所需字节。
- 关闭时等待计划释放、前驱失败/停止未知、分配和event失败；parent FIFO与设备串行保持。
- 通过确定性单元测试及真实公开 API 的板端场景提供证据。未覆盖的形态明确列出，CI绿不能替代功能闭环。
- 新错误符号不与现有 BASE−3/−4 或 DFX BASE−5 冲突；不新增 PTO_ / PTO2 名称。按 github-pr/fix-pr 流程交付单提交。

完整机制与E1–E39/S1–S7验收映射见 [设计稿](p4-auto-resource-admission-design.md)，勘误优先级见本稿开头的评审。

## 合入后实现澄清（2026-10-17）

#2596 已合入 `a2b0ad2`；本节记录实现行为与代价，不改写原审批记录。

- `slot` 是可复用执行资源组的内部索引；run 的 generation/epoch 区分复用前后的身份，arena bank 映射独立。取消固定 2/3 套准入不等于取消资源身份。
- 自动模式身份目录按 64 KiB 表预算容纳 168 项；目录不预分配各组设备内存，但它仍是有限上限，到达上限背压。
- 冷启动从一个逻辑 run 开始，首个完整 run 退休且 parent 折入容量反馈后才扩大准入。相比旧默认两份请求，首对请求不能重叠准入/prepare；没有量化延迟或吞吐影响。该行为已写入 Worker 文档，现补充新旧对照。
- 普通 Python 调用路径与同线程跨 native context 的嵌套 prepare 必须区分；源码复核发现后者会丢失外层线程局部事务身份，需要窄修，尚未执行复现；不能由普通多线程测试推定安全。
