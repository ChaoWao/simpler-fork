# 内存归一化首步：统一管理四类 workspace 的额度与地址寿命

状态：用户已明确批准本合同实现并交付一个 PR。2026-09-23T07:54:17.894796+00:00
基线：`44178c9f7`。本文件是审批边界；原作者的细节稿与本文件冲突时以本文件为准。

[先看工作过程与扩容例子](memory-workspace-how-it-works.md)

## 要解决什么

现有 retained_temp 与三个 arena 各自管理扩容、释放。扩容失败保全已由 #2416 交付，但成功换块仍不等于旧地址可以释放。
本步让这些区域交给一个 workspace 管理器：明确总额度、哪一代块仍被使用，以及何时可以复用。
例如前一次运行的回拷还持有地址 A，新一次准备需要更大空间，只能在额度内另取 B；不能释放或覆盖 A。A 的所有消费者结束后才归还给管理器复用。

## 总体方向与首步范围

总体设计仍是 eager 与 capture 共用：稳定 backing blocks、内容覆盖许可与地址存活分别判断、图和在途 replay 持有真实引用。capture 前准备容量；capture/launch/replay 不扩底层块。

**本 PR 只迁移同进程 L2、onboard a2a3/a5、HBG/TMR program eager 路径的 retained_temp 与三个 arena。**
新增显式 `workspace_budget_bytes`；未设置时行为不变。设置非法值、sim/kernel 或 L3/子进程路径时在启动副作用之前拒绝，不能悄悄忽略。

这不是 capture 已可用的交付：图引用交接、销毁/更新/replay 接口和父子进程关闭协议不在首步。它们后续用同一管理器扩展，仍需具体合同，不能把本次批准解释为它们已获批准。
外部 tensor、run-result/DFX、注册代码/ELF、RTS 和 provider 内存不迁入本步额度；报告明确 coverage_is_partial，不能把该数称为整个 Worker/NPU 总显存上限。

## 内存行为

1. init 固定有限额度，生命周期内不自动提高。按真实 backing block 计费，包含保留旧代、暂存新块、对齐和闲置。原有区内容量足够且无冲突消费者时复用；不足时图外 prepare 追加，超额明确失败。
2. 新分配、记账和新计划全部准备成功才发布。失败保留已发布的地址/容量/计划；释放失败的暂存块仍有明确 owner，持续计费，不能丢指针或假报释放。
3. 已发布地址不搬迁。每个消费者按真实 run/slot/context 代际持有引用，最后设备使用、回拷、binding 释放等事实满足才复用内容。一次 wait 返回或 reset rc 为0不能替代这些事实。
4. 首步保持原消费方的独立分配粒度，不额外合并所有区域为一块，不改 P4 调度/设备并发/现有同步策略。
5. 多代块没有按两个槽截断的列表；所有仍持有的代都进入同一账本。用于安全判定的“曾发布”标记必须不可回绕；不能因统计溢出误判没有资源。

## 失败与关闭

- 先停止新提交，保留已受理工作的既有排干路径；不能调用会额外丢弃未启动任务的替代接口。
- 在公共 Worker 的 Buffer 释放批次之前，单独检查受保护 workspace 是否仍有可排干的使用者。该检查与后续清理不能放在一个遇错仍继续的 journal 批次中。
- 预算启用状态独立保存；设置入口与查询入口同时具备才允许启用。启用后查询失败、未知 schema 或缺失 context 均阻止受保护清理。startup rollback 同样遵守；只有已证实从未拥有相关资源时才能豁免，查询失败不能冒充该证明。
- 查询是持相应锁得到的一致分类快照。未启用路径不增加关闭拒绝。live 消费者仍可排干时保留状态供后续关闭；不能继续进入 device finalize 后再声称可以从头重试。
- 已无法证明最后消费者结束的块整体隔离，不单独 free/unregister；所有代均纳入分类。保持既有 program reset 策略，不新增 reset，也不把 reset 成功当成回收证明。
- 终局清理先把结果写入既有定长记录，再清空 allocator 的旧地址表，最后尽力记录日志。二次 close/析构不再对已退出账本的旧地址发 free。日志失败不能阻止清账或覆盖原错误。
- 释放失败/隔离须如实报告。设备回收可能未知；host VA 映射可能留到进程结束。新建 Worker 不保证拿回这些字节。

## 分配器接线约束

Module 节点与 allocator 跟踪节点都在设备分配之前预留。move-only reservation 持 allocator 锁直至 commit/cancel，预留到插入期间不得被其他写者耗掉容量；单个成功设备分配之后的记账提交不再分配 host 内存。
锁顺序为管理器准入锁→allocator锁。该 Module 分配在锁内执行，其他分配的记账会等锁；**不声称未改动的其他 rtMalloc 调用本身也全部串行化**。
finalize 的分类/记录回调只访问既有存储，在清空前落账；非 Module 分配的失败用固定聚合记录，不在清理时新造无界缓冲。
同版本重建 host/runtime/绑定；新增 descriptor 代际字段与 C ABI 必须落实大小和能力校验，不能接受旧布局后越界读写。

## 代价与用户可见变化

- 显式启用后，超额 prepare/bind 失败；保留旧代和扩容瞬间新旧共存会提高峰值，低空闲显存下可能更早拒绝。
- 增加每块/每 run 引用与证据记录、分类查询、同步和分配持锁开销；暂无性能收益承诺。
- 未证明安全时 close 可拒绝并保留资源。终局失败可能保留映射或设备回收未知，不将其包装为自动恢复。
- 首步 L2-only；L3/capture 并未被解决。收益是统一四类 workspace 的预算和所有权基础，不是一次交付完整统一池。

## 一个 PR 的验收边界

静态与新增针对性覆盖：默认不变/非法与不支持路径提前拒绝；容量内复用；至少三代保留；增长失败保持旧计划；两层记账 host 失败；回滚 free 失败仍有 owner；已启用但查询失败拒绝清理；startup rollback 一致；清理日志抛出仍完成记录/清账；二次 close 不触碰旧地址；实际 L2 公开路径接线。
新增未执行 case 可按既有授权首跑；已执行测试不重跑，CI 重试仍逐项单独授权。不合并。
