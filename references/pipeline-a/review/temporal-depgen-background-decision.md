# DepGen 依赖图后台输出：一个 PR 的实施合同

状态：用户于 2026-09-29T09:54:33.091001+00:00 明确批准该依赖图后台输出合同，交付一个 PR；原 temporal 会话负责实施。manager 已审作者 rev4，以下为控制合同。
基线：main 35e9331b5；本合同控制下列具体边界。

## 要解决什么

DepGen记录任务之间的依赖，输出供定位/分析使用的 deps.json。TMR目前在设备完成后，由主机接收、核对记录，再回放依赖并写文件；这些主机收尾占住run返回路径。

本PR让可靠交接后的记录、身份和输出路径独立归后台所有，主机回放/整理/写文件可与下一run的串行设备执行重叠。适用本地L3、a2a3/a5 TMR（onboard及sim），通过既有 collect_across_runs + enable_dep_gen 显式开启。HBG的主机构图对象归属不在本PR，设备仍串行、诊断独占保持。

## 一次与连续运行的过程

1. launch前为本run登记身份和输出路径、预留输出名额并检查采集计数初始化。最多两份尚未发布的run数据，包含当前正在采集的一份；不是设备slot绑定，也不是只能运行两次。满额时拒绝新run，不让已启动的run等待写盘来释放设备缓冲。
2. 设备执行期间接收记录至独立主机记录块。块分配前计费；记录超额或归属错误使该run不可发布，不能阻塞接收链路或悄悄截断后仍报告完整。
3. 设备完成后仍同步排干接收、读回终态并核对计数。这些涉及设备安全交接的动作不移走。设备完成未知时，不读共享终态、不抢救未交接记录、不产该run的新文件；已有主机副本按既有reader退出边界清理。
4. 将完整记录、计数结论、run身份和文件路径交给一个后台writer。run返回不再保证deps.json已写完。下一run正常采集自己的数据；任务ID在不同run可以重复，不作为全局唯一键。
5. writer逐份回放依赖、自校验并原子发布deps.json。读取文件前调用flush_diagnostics；旧同名目标不覆盖。close沿既有路径flush/join并报告错误，不承诺慢盘下close有界。

## 内存怎样限制

每个collector独立默认256 MiB主机保留/输出预算，不与其他collector或设备互借，不是整个Worker的内存上限。预算包括记录块、两份输出元数据及受限路径存储、1 MiB序列化暂存、对齐空间，以及实际回放工作存储。

- 记录块在分配前收费，物理释放后才退费。
- writer取得一份输出后才申请其回放工作区；另一份sealed输出只保留已计费记录。因此只有一个writer工作区。
- 固定可计数的任务/参数/双tensormap按实际规模一次申请。双tensormap当前每份回放约有17.1 MiB基础开销。
- 一个tensor可关联多个producer，依赖边和索引按实际增长分段收费；rehash的新旧表同时存在时同时计费，分段索引本身也纳入。不得借容器、序列化或手工切片绕过预算。默认路径保持无此预算限制。
- 所有乘加、offset、alignment、ring/local-id范围和table探测边界在分配/访问前检查。超额、OOM或格式异常均不发布新图；预算不足不等待未来退费，不发生writer等自身释放的死锁。

预算外保留既有固定设备池约18.5 MiB、非SVM平台同等host shadow和固定控制区；它们按collector/device context分别存在。线程栈、分配器内部元数据与系统文件缓冲不承诺计入上述应用层预算。磁盘文件占用不属于主机预算。

## 完整性与错误

只有接收、归属、终态计数和回放自校验全部可信时发布完整图；deps.json格式没有部分图标记，本PR不新增格式。丢记录、计数未知、读回失败、未交接buffer、无效身份、回放失败或写盘失败均不产该run的新图，保留旧文件。

后台模式诊断错误保持到runner销毁，通过flush/close明确报告；不把已知设备成功改写成设备失败。后台准入失败在launch前返回；要撤销同次已准入的其他collector，避免泄漏输出名额。

设备三个计数器的八处增加操作改为饱和，UINT32_MAX表示未知，防止回绕伪装成完整。会增加设备计数开销；共享AICPU镜像中的代码也会变化，需验证兄弟runtime兼容，不承诺性能收益。

## 未开启后台时有什么变化

正常完整run的文件名、路径、schema和内容保持，仍在原边界同步输出。计数饱和、D2H/计数重置失败、无法解析buffer、截断、错误run身份和无效回放索引等情况会更严格地拒绝输出并记录错误；计数重置失败不拒绝默认run，既有run返回码及log通道保持。默认模式不增加DepGen的flush粘性错误，也不新增256 MiB限制；默认文件发布方式不在此PR改造。

## 验收

真实Worker路径运行两个不同拓扑（允许重复run-local task ID），flush后分别核文件路径、任务和边结构；占用目标路径应报错且不覆盖。生产collector/replay回归覆盖暂停writer时后续run仍独立、第三份准入拒绝、空run、计数饱和、D2H/初始化/归属失败、多producer/多段overflow、预算不足和两份输出费用结清。清洁默认输出逐字节比对，新增拒绝仅按指定通道报告。

只运行真正新增测试一次，既有测试由自动CI验证；不合并。新提交必须经理静态复审、阻塞反馈处理且相关CI完成后才Ready。
