# DFX：ScopeStats 作用域统计后台输出 — 用户已批准

基线 `410502f7b`，原 temporal 作者 final contract 已完成 manager 静态审查。用户已批准实现并交付一个 PR。

## 现在做什么，改后怎样工作

ScopeStats 记录 runtime 各作用域的任务窗口、heap、依赖池等资源使用情况。今天每次 run 收尾都要接收记录、核对设备计数、整理并写完 `scope_stats.jsonl`，才能继续。

本次保留设备完成后的接收排干（quiesce）和终态读取。只将已经独立持有的主机记录、该 run 的容量快照和输出路径交给后台线程。例如 A 的设备工作及记录交接结束后，B 可以开始串行设备执行，同时后台整理并写 A 的统计文件。

`run` 返回不再保证统计文件已完成；用户读文件前调用现有 `Worker.flush_diagnostics()`。不新增 session 或公共选项。

## 范围与运行过程

- 仅本地 L3 chip 子进程、TMR、a2a3/a5 onboard 与 sim，显式 `collect_across_runs=True` 且该 run 启用 ScopeStats。
- 保留设备串行和诊断独占；不将接收排干移出边界，不开放 L2、remote、L4、kernel 或 capture。
- HBG 无 ScopeStats 生产者，保留现有元数据文件行为。DepGen 是后续独立工作。
- 准入先预留一个导出位置；最多两个未发布 run。第三个在设备提交前拒绝，不无限排队。
- 设备完成可证明时：排干已发布记录 → 检查终态读取成功 → 补收尚未发布的当前缓冲 → 固化记录、计数、容量与路径 → 后台输出。
- 设备完成或可靠终态不可证明时：该 run 不产生新的统计文件，不抢救读取共享头或当前缓冲，不增加 drain/reset；报告持久诊断错误。活跃主机副本保留至既有采集线程 join 后丢弃；这不授予释放设备存储的权利。

## 完整性与文件语义

实际接收数和成功保留数分开计量；预算不足时停止保留，继续接收计数，不让写盘阻塞接收线程。已完成设备的接收数加设备丢失数应与设备产生数一致。

四处设备计数改成饱和累计，达到 UINT32_MAX 标记“计数未知”，不能回绕成零后误报完整。丢失、fatal、计数未知均通过元数据和 flush 错误明确报告；设备原始错误保持首要错误。

文件名和记录行保持，后台模式元数据增加采集结论、计数是否未知、接收数、保留数四项。先写临时文件，再无覆盖地发布最终名称。写入、关闭或发布失败必须使 flush 失败，不能被“采集完整”覆盖；既有同名文件不删除、不覆盖，也不能算本次成功，可能留下的临时证据需清理。

错误持续到 runner 销毁；存在未知完成的隔离记录时，后续启用 ScopeStats 的 run 拒绝准入。未启用 ScopeStats 的 run 不因此新增拒绝，但仍受既有设备错误与准入规则限制。

## 资源与兼容代价

每 collector 独立 256 MiB 主机额度，与其他 collector 相加。固定约 64 KiB 记录块按容量记账，另预留两份元数据/路径和 1 MiB 写入暂存；避免随记录数构造巨型字符串。慢盘会占住两个位置，后续 ScopeStats run 可能被拒绝。

设备饱和计数增加比较/加法开销，所有启用 ScopeStats 的 run 都受影响，包括未启用后台模式的 run。默认路径普通计数的文件行为保持；达到计数上限时，原本回绕的 total/dropped 数值改为 4294967295。默认 run 返回语义保持。无延迟或吞吐收益承诺。

flush 沿现有公共入口共享一个超时截止时间。close 报告诊断错误，但已有 writer join 在磁盘永久阻塞时不承诺有界返回。

## 实施审查与验收重点

真实生产接线覆盖两种 runner 的两个收尾分支、ScopeStats 单独启用、未提交回滚、公开 flush/close、collector 重建。不能照搬当前忽略复制返回码的 reconcile 写法：任何必要 D2H 失败均使终态不可信，禁止读取失败后残留的字段并发布成功。

新增验收覆盖：真实生产者发布/未发布缓冲恰好计一次、饱和与 fatal 分类、容量拒绝、两次未发布与第三次拒绝、临时文件发布失败、未知完成零共享读取和 join 后丢弃、连续多 run 身份及默认行为。仅执行尚未执行的新 case；已有用例和 CI 重试仍需逐项授权。
