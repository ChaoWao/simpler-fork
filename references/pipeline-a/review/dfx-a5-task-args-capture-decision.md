## 以下为延期方案的历史设计

## 为什么需要这一步

A5 HBG 的常驻 AICore 调度器直接执行图内任务，AICPU 看不到每个任务开始和结束。当前 ArgsDump 没有这条路径的实际生产者，因此四后端完整验收中的 A5 HBG 仍失败。

例如任务 A 写出 X、B 读取并改写 X：run 开始时复制，拿不到 A 的输出；run 结束时复制，只能拿到 B 改写后的值。必须在各任务实际读写的边界复制。这个方案服务于参数诊断，不是 capture/replay 模式。

## 一次任务如何工作

1. 仅启用 ArgsDump 时准备控制存储。被选中的任务所有参与核在执行前到达同一屏障；最后到达者发出一次带完整 run/task 身份的请求。
2. AICPU 从现有参数 arena 与元数据队列预约空间，分块复制输入。每个 dump lane 同时只持有一个未提交预约，复制一块后返回调度循环，继续检查其他核和错误。
3. 空间暂时不足时回复 WouldBlock，保留排队位置，不重复记丢失，不在 AICPU 服务函数里自旋等待。已持有预约的复制必须继续推进，不能被等待同一预约空间的请求挡住。
4. 全部输入复制完成后发布该阶段的最终确认，各参与核才能执行。任务执行后先完成写回，再共同等待输出复制；完成输出阶段、所有参与者离开后，才发布任务完成，允许后继覆盖数据。
5. 阶段身份 phase_seq 固定；每次分块或重试使用独立 request_tick。其他参与核只等待本阶段最终 Sealed/Aborted，不把进度回复当完成。旧请求/确认不会因为存储复用被误认。
6. 主机沿现有按 run 接收与后台文件流程处理记录，读文件前仍需 flush。记录实际属于哪个 task、哪个参数、BEFORE/AFTER 都保留。

## 资源与性能代价

- 每个启用 ArgsDump 的 run 新增约 18 KiB 设备控制存储：108 份请求、108 份确认和 72 份任务调度位置状态，每份 64 B；这是内部调度位置，不是新增用户 pipeline 深度。
- 设备侧 AICPU 私有状态预计约 2.2 KiB；实现必须按实际字段和对齐重新核算，不能拿估算替代布局验证。
- 复用原 payload arena、元数据队列及现有输出容量，不增加第二套 payload 池或新的用户参数。保留任务和控制存储直至最后消费者安全退出。
- 每个被采集任务增加两次多核会合，每个参数至少一次 GM 往返，大或非连续 tensor 还增加分块往返。同 lane 的大参数可能延后其他任务的采集；显著扰动被观测任务是接受范围，不能承诺延迟收益。
- PARTIAL/HYBRID/FULL 选择语义不变；关闭诊断时不分配上述资源，也不进入会合协议，不宣称绝对零指令开销。

## 满额、失败与关闭

- 等待者达到既有 watchdog 条件时发出 abort 并报告错误，不能仅凭自己超时就离开，任由 AICPU 继续读已经复用的 tensor。
- AICPU 停妥正在复制的块后回传 Aborted；有未提交预约时回滚其 arena 偏移并只记一次拒绝，没有预约时不新增拒绝计数。先前已完整提交的参数记录保留。
- aborted 任务位置不在本 run 复用；未完成阶段不伪造成功终态，相关采集完整性报告 unknown。
- watchdog 不保证 AICPU 失联时一定收到确认。若确认无法取得，参与核保持停车，走既有停止/隔离流程；只有确证生产者停止后才回收，停止未知保留资源并报错。关闭不承诺硬实时完成，也不新增进程内恢复。
- 共享任务状态仅使用现有 GM 原子或设备直读写，不对含其他核原子字段的整条 cache line 写回。请求/确认各自单写者，与共享状态分离。
- 公平性只保证 AICPU 首次观察到请求后的排队次序；不声称能还原跨核真实发布时间。最终确认必须保留至所有本阶段读者消费完，才允许复用对应确认存储。
