# HBG 主机依赖图后台输出：一个 PR 的实施合同

状态：manager 已审设计 rev3；用户已批准实现并交付一个 PR。2026-09-30。

## 交付什么

现在 HBG 在主机构图完成后，于 prepare 调用内整理并写出 `deps.json`，提交线程要等文件完成。已有 TMR 后台依赖图输出不覆盖这条主机构图路径。

本 PR 让本地 L3 显式开启 `collect_across_runs` 时，将完成的 HBG 主机图交给独立后台写入者。例如第 N 次构图完成后，提交线程可以继续发起设备工作及下一次调用；后台持有 N 自己的任务、参数、tensor 描述及边，不再读取下一次构图会覆盖的线程局部状态。读取文件前调用 `flush_diagnostics()`。

仅覆盖 a2a3/a5 的 HBG program（含相应 sim）。默认同步输出、L2、TMR、设备串行和诊断独占不变。不增加 session 或 capture/replay API，不改变用户 tensor 所有权。

## 从构图到文件

1. 在实际构图线程、成功 bind 后，先取得 exporter 操作引用，再将五个图记录 vector 连同 run 身份及输出路径转移出去。记录构图是否真正开启；合法空图输出空图，错误线程或未完成构图报错，不能静默漏图。
2. 后台最多保留两份未发布的图，合计应用层保留预算默认 256 MiB，按 vector 的实际 capacity 及固定路径/记录/1 MiB 写入暂存计费。这不是设备 slot 数，也不是最多只运行两次。
3. 两份已满或当前图超过可用预算时，当前调用直接同步写图，不拒绝计算。此时提交会等待写盘，不能保证后台重叠。
4. 后台和同步回退都先写独占临时文件、检查 flush/close，再以不覆盖已有文件的方式发布 `deps.json`。目标已存在或写盘失败时保留旧文件，记录持续错误，flush/关闭时明确报告。
5. flush 等待此前已提交的后台/同步写入并读取错误；与它并发且尚未提交写入的调用可在线性化点之后完成。超时不宣称文件已完成。
6. 关闭先禁止新操作，再等已有操作及队列完成，最后 join writer、释放预算；构造失败后的析构同样收尾。所有异常出口必须释放操作引用，并在解除写入登记前记录结果。关闭等待没有新的硬超时承诺，慢盘会延长关闭。

## 特别需要理解的边界

- HBG 图来自主机构图，构图完成就可输出，因此设备尚未 launch 或执行失败时也可能有图。这延续当前含义，图不证明设备成功执行。
- 256 MiB 仅限制构图后交给后台保留的记录，不限制构图时峰值、同步回退、线程栈、分配器开销和磁盘占用。合法的大图可能超过该预算而回退同步。
- 输出路径加文件名须适配固定 4096 B 路径空间，过长明确报错；后台模式不覆盖同名旧图。默认同步模式保留原有覆盖行为，但补齐末尾写盘错误检查。
- 增加保留主机内存、锁、线程与记录整理开销；不承诺延迟或吞吐收益。
- 新接口保留现有 `dep_gen_host_graph_emit` 签名，不接管 #2487 的图参数载体；二者共享 runner 接线文件，后合入者必须在新 main 上验证组合。

## 验收

真实 Worker.submit 连续两张不同图，flush 后分别核对各自完整拓扑和输出身份；开关前后同图字节一致；空图、跨提交线程、close 收尾、同名文件保护、预算回退均覆盖。确定性暂停点验证 flush 对同步回退的等待、关闭与未提交 seal 的竞争，以及未显式 finish 的析构路径。测试由新提交 CI 执行，不重复已有本地测试。
