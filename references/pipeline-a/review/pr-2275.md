## 非阻塞意见

### 1. weak default 仍允许共享 bank 缺失 probe 的 runtime 进入

位置：`src/common/platform/onboard/host/c_api_shared.cpp:904–912`；weak 定义在 `:107–112`。

新增分支在发现共享 bank 后仍调用 `prepared_run_config_compatible_impl`，而其 weak 默认返回值仍是 `1`。
因此 PR 动机提到的“共享 bank、支持 concurrent prepare，但忘了提供 probe”仍然会被允许。

这不是新增回归：原代码也允许。当前 TMR 两架构均有强实现，HBG 使用独立 bank，故未发现现有 runtime 的错误路径。
但“require the probe”只能理解为调用兼容性入口，不能理解为强制 runtime 提供了有效检查。

建议：现在 HBG 已不再依赖默认放行，可考虑让缺省实现返回不兼容、保守回退 depth one；或者明确将这一点保留为后续合同加固，避免把本 PR 记成已经解决缺失 probe 的风险。

### 2. 现有测试证明行为保持，尚未直接锁定新增分支

PR 没有新增测试。HBG 重叠和 TMR 不兼容回退在改动前也应通过，因此不能单独证明“是否调用 probe”这一新规则。

建议将来补一个针对接口行为的用例：probe 有调用计数且返回不兼容；独立 bank 的后继应成功 prepare 且计数不变，同 bank 后继应调用 probe 并在 bind 前回退。另覆盖排除自身 reservation 和前驱 reservation 释放后的结果。

这些是新增 case 的建议，本次未编写、未执行；不把行为保持重构缺少此用例判为当前正确性 bug。

## 机制核查

1. **bank 来源可靠。** `ChipWorker::init` 验证 arena 三类资源的 copy count 一致；`arena_bank_for_slot` 再通过 `pipeline_resource_slot` 选择 bank。HBG 的 arena 为 `HOST_PER_RUN`，TMR 为共享 `DEVICE_SCRATCH`。
2. **reservation 与资源寿命对应。** `try_reserve_native_run` 拒绝相同 slot 重入；当前最多一个 active 前驱加一个准备中的后继。reservation 保留到 cleanup/finalize，查询时使用同一把 `native_run_mu_`，且排除本 run。
3. **HBG 路径保持安全。** 新代码跳过 probe，但 `setup_static_arena` 只改给定 bank 的三个 region；扩容、零大小释放和失败回滚不会触及前驱所在的另一个 bank。
4. **TMR 路径保持原检查。** 同 bank 时仍在 provision/bind 之前检查 layout key。强 probe 校验 task window、heap、dep pool；不匹配或 cache miss 返回不兼容。匹配时 bind 使用缓存地址，不重建或上传共享 arena image。
5. **捕获图保护未变。** kernel mode 的 grow/release 拒绝发生在首个 `commit_region` 之前，不会进入会释放既有 region 的失败回滚。
6. **并发边界未扩大。** 新查询是一次加锁的 reservation 快照，没有持锁调用 runtime hook；它没有提供跨检查和 bind 的通用事务锁。当前 lane 串行驱动及单 active/单 prepared 约束继续成立，P4 改准入时必须重新保持这些条件。
7. **接口边界。** 新增的是内部 C++ 查询；未改 C ABI、Python API、IPC 或 device wire image。两种 onboard 架构使用公共实现，sim 路径未改。

## 对 A 轨计划的修正

此前将 arena 扩容/回滚保护笼统列成“需要新实现”过重。现有二槽路径已具备两种安全策略：

- HBG：每 slot 私有 bank，扩容/回滚局限于自身。
- TMR：共享 bank 必须命中兼容布局，否则延后 prepare，等前驱结束再改变布局。

本 PR 将两种情况显式区分。A 轨可以继续保留上述隔离/背压策略，不必为此强制新增旧代引用计数。
但它不是 `setup_static_arena` 内部的通用在飞引用保护；P4 放开多 launched 后，不能直接移除 prepare 前的兼容性检查或过早释放 reservation。
TMR 每 run 错误结果保存、重型 DFX 准入和 P2 完成机制仍是独立事项。
