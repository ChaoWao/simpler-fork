## 1. 背景与问题

普通 Host Tensor 默认 H2D，设备获得独立副本；原生 HOST/NONE 保留 Host 地址，不能据此推断 A5 kernel 可用该地址直接访问 Host DDR。Engram 的完整表可能不适合复制到 HBM，需要设备按索引读取同一 Host backing 的少量行。

本 PR 提供普通 Buffer/Tensor 上的按调用 MAP：

```python
buffer = worker.create_buffer(nbytes)
tensor = buffer.tensor(shape, dtype)
args.add_tensor(tensor, TensorArgType.INPUT, transfer=TensorTransfer.MAP)
worker.submit(entry, args).wait()
worker.release_buffer(buffer)
```

同一 Tensor 可在另一有序调用选择 H2D。映射只建立访问，不承诺快照、同步或自动 gather。方向、数据结构和应用层算法仍由调用方定义。旧公开 `map_view/unmap_view` 方案已被取代；此前评审称其“已对齐”漏读了当时新增的 MAP 讨论，不能沿用该判断。

## 2. 机制、收益与成本

`TensorTransfer.MAP` 通过现有 TaskArgs enum、序列化与校验传递；Worker 的共同 L2 准备路径验证 callable grant、ownership、context、能力以及可写 H2D/MAP 重叠。`ImportRegistry.materialize_args` 逐参数生成 binding，MAP 转成内部 DEVICE/NONE，保留原始 Host descriptor 和几何。原生参数与映射参数不再被按 backing identity 折叠为一个地址。

`HostMappingRegistry` 隶属该 Worker 的 ImportRegistry，持有真实 Buffer、规范 descriptor 和上下文；按 whole Buffer 缓存 ACL registration，按 run_id 保留每次调用使用。首次 registry 发布由 Worker registry lock 保护；Buffer owner lock 先于 mapping lock，准备与释放在同一边界串行。A5 backend 调用 `aclrtHostRegisterV2` / `aclrtHostGetDevicePointer` / `aclrtHostUnregister`，不准备通信域或 URMA 资源。

普通完成通过 `_release_source_uses` 退休 Host uses，健康注册保留到显式 Buffer release。busy 拒绝不关闭接纳；实际 unregister 前关闭接纳，失败保留 backing/context 供重试；未知完成保留资源。异常 owner teardown 先清 idle registration，再尝试 native finalize；未知 MAP use 不支持自动恢复，这是明确边界。

`HostSharedMemory` 使用 ctypes carrier 和真实 mmap export 的 finalizer，使临时 memoryview 创建的 NumPy 数组及其切片也保留存储。普通 Buffer 和通信域复用导出机制，allocation/unlink 所有权继续分开。代价是释放要求所有 CPU exports 已退休；相关 scene/example 调整了快照读取和 traceback 持有关系。

收益是省去整表 Device 副本与稳态全表搬运，并且公共 API 无独立 mapped Tensor、mapping reference 或用户计数器。代价是 submission 的验证、锁和注册缓存，以及所有 Host 调用的 use 管理；缓存/用途分离合理，但必须覆盖每条 completion authority。锁开销和实际稀疏读取吞吐没有本轮性能测量，不宣称速度提升比例。

## 4. 剩余问题

### Must fix · P2：framework 完成遗漏 Host use 退休

引入点是 [Worker._prepare_l2_args 的无条件 Host acquire](https://github.com/hw-native-sys/simpler/blob/c15ba2529ae0a34113c4cac9e4a5498109cfb063/python/simpler/worker.py#L14321)。`HostMappingRegistry._select` 不只选择 MAP，还包括本 Worker 拥有的 HOST/NONE 与 H2D。borrowed framework 路径允许 HOST/NONE，因此也会建立 `_uses[run_id]`。

普通 `_release_source_uses` 已新增 `host_mappings.release(run_id)`，但 [framework 专用 _finish_framework_submission](https://github.com/hw-native-sys/simpler/blob/c15ba2529ae0a34113c4cac9e4a5498109cfb063/python/simpler/worker.py#L14423) 只释放 device source，随后删除 call/run 记录并发布 terminal，没有退休 Host uses。

具体触发：

1. borrowed L2 创建 owned Host Buffer，以 `transfer=NONE` 作为 IN control 参数准备提交。
2. framework 接管 ticket；native 已确认完成，`_retire_framework()` 返回 true。
3. handle 已 `safe_to_release`、native live set 已空，但 Host registry 仍有原 run_id。
4. `release_buffer(buffer)` 抛 `Host Buffer has in-flight or unproven uses; wait before release`。继续 wait 不会重新进入已经完成的退休路径；owner close 在释放 Buffer 阶段也受该引用阻挡。

阳性对照：完全相同参数、相同 recording transport 走普通 `handle.wait()`，Host uses 为空且 Buffer 正常释放。HBG/TMR 各一对用例。现有 framework fixture 只提交空参数，因而没有覆盖新增所有权。

修正要求：framework 的已证明完成/取消路径在丢弃 run identity 前退休 Host uses；保持 device source 的“失败不重放不确定 decrement”规则。添加 owned HOST/NONE + framework retire 的回归，验证 Buffer release 和 Worker close 都能结束；失败/unknown completion 仍保留使用。无需新增公共 API，也不应禁用原有 HOST/NONE 来掩盖遗漏。

### Should fix / 验证要求

修复后取得该最终 head 的 A5 TMR/HBG 数值与 teardown 证据。旧 A5 job 的成功是已有资格证据；当前 common completion 与 HBG runtime 已有变化，应覆盖当前组合。
