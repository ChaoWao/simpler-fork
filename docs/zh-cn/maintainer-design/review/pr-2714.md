## 1. 背景与目标

Engram 的大表保留在 Host DDR，A5 kernel 按需读行；无需先在 Device 上复制整表。#2730 明确独立交付同进程、拥有 backing 的 direct L2、单 A5 的同步 MTE 访问。#2731 再消费此合同完成 L3 多进程映射和非 self URMA 异步读取；本 PR 不关闭 #2657 的完整目标。

例如 `buffer = l2.create_buffer(nbytes)` 后，native Tensor 继续表示普通 Host 存储；`mapped = l2.map_view(native)` 选择 Device 可用的访问。kernel 对 mapped 参数读写原 backing，`wait()` 后 CPU 直接读结果。普通 native H2D 仍然可用。

旧评审中的独立 `access` selector、限定只读等建议，以 #2730 最新正文及 #2721 共享读写原则为准。本 PR 没有增加该 selector；暂时保留主线既有 grant 检查属于兼容迁移边界，不要求它先完成 #2460 的所有权限字段迁移。

## 2. 方法与机制

`BufferDescriptor` 保持身份、HOST 位置和容量。144-byte Tensor 的 142–143 字节保存本进程 mapping reference，零值选 native；原 141 字节仍是调用的 transfer。映射记录保存原 descriptor、精确 Tensor、Host/device 地址及 closing 状态，同一 Buffer 的多个 view 复用一次完整 ACL 注册。

`ImportRegistry.materialize_args` 分别用 identity 和 `(identity, reference)` 解析 native/mapped 地址，随后沿既有 ChipTensor/TaskArgs 路径执行。映射不创建新 backing identity，依赖分析仍识别别名。mapped 参数只接受 NONE；L3、Host compute leaf 和 Remote 编码拒绝不支持的映射转发。

A5 host runtime 提供 `host_ddr_map_ctx`/`host_ddr_unmap_ctx`；ChipWorker 检查实际加载的符号，调用 ACL HostRegister/GetDevicePointer。部分注册失败保留清理债务；Python registry 强引用 backing 和 ChipWorker，避免未证明完成时提前释放。submit 在 native admission 前登记 run 使用，完成时释放；unmap 在后端调用前置 closing，失败只保留重试权。注册表内部锁覆盖 acquire/unmap 的竞争，但注册表自身的首次创建缺少相同保护，见下文。

本地同步 MTE 不需要通信域或 URMA workspace。任务方向用于既有 IO/依赖，IN 不构成硬件写保护。CPU/Device 的同步仍由调用者与任务完成合同承担。

## 4. 剩余问题与风险

### P1：Host 导出不能兑现示例用法下的派生数组保活

位置：[buffer.py:356–371](https://github.com/hw-native-sys/simpler/blob/6cbe34222e621782f0ae5ceccaace1a9764ab2d8/python/simpler/buffer.py#L356)。

```python
array = np.ndarray((16,), dtype=np.int32, buffer=buffer.host_view())
buffer.close()  # 实际成功，array 仍然活着
```

在本地 NumPy 2.2.6，`array.base` 是 mmap；临时 memoryview 被丢弃后，close 成功且 `array.base.closed == True`。数组仍指向已解除映射的内存；初次探针中 pytest 展示该数组时实际触发 SIGSEGV。后续安全探针只记录 owner.closed、先删除数组再断言，稳定复现，避免错误报告再次解引用悬空内存。

阳性对照：memoryview 切片与 `np.frombuffer(buffer.host_view())` 均使 close 抛 BufferError。问题不是原有 raw `.shm.buf` 被误归到本 PR，而是新增 `host_view` 承诺安全保活、且新示例仍使用会丢失该保活的 NumPy 构造方式。

需要明确并落实可执行的 Host export 寿命合同：覆盖常用 NumPy 派生对象，或明确要求调用者显式持有 export、同步调整样例并测试这个受支持用法。不能继续把所有派生对象都描述成自动受到 close 拒绝保护。

### P2：并发首次 map_view 发布两个注册表，成功返回的 view 随即失效

位置：[worker.py:13186–13196](https://github.com/hw-native-sys/simpler/blob/6cbe34222e621782f0ae5ceccaace1a9764ab2d8/python/simpler/worker.py#L13186)。

线程 A/B 同时观察 `registry.host_mappings is None`，各创建 HostMappingRegistry。A 返回其 view 后，B 覆盖 `registry.host_mappings`；后续 materialization 只查 B 的表。两次 map 均返回成功，其中一次 submit/materialization 却得到 `stale or foreign Host mapping reference, descriptor or range`。操作 lease 只保护 close 等待，不互斥首次发布；每个 registry 内部的锁也无法保护这一层。

确定性探针使用实际 Worker/registry/当前 bindings，仅以 thread trace 在上述 None 判断之后协调交错，ACL 使用现有 fake fixture；两个不同 Buffer 的返回结果为 `resolved` / `stale or foreign ...`。先建立 registry 后，相同并发调用两者均 resolve，作为阳性对照。

需要使 ImportRegistry 和 HostMappingRegistry 的首次发布与实际使用保持单一权威，补首次并发映射回归；不要求重写已有 Buffer 架构。

### 需确认的设计取舍：累计引用上限

`host_ddr.py:112–114` 使用全进程单调 counter 和 16-bit reference。实际顺序 map/unmap 65,535 次且 live records 为 0 后，下一次仍抛 exhaustion；新建 Worker 不重置全局计数。这是 **ABI 文档已明确写出的限制**，不是隐藏 bug，也不单独作为本轮 request-changes 理由。需确认长期服务是否接受该累计预算；不能把它误读为“最多 65,535 个同时存活 view”。任何复用方案都须继续拒绝陈旧引用，不能简单回绕。

未覆盖范围：L3、多 rank、非 self URMA 与 overlap 在 #2731；不因本地硬件通过而认定这些目标完成。既有 Buffer.access 迁移归 #2460，不能以本 PR 删除所有检查代替成对迁移。
