## 1. 背景与问题

L3 host 向 L2 AICPU 发消息、L2 调用 AIV 后回传结果，main 已有这样的 worker-chip 队列。旧实现自行维护 Python 算法、native endpoint 和 12-scalar L3Q2 布局。队列协议与资源部署耦合，后续其他结构容易再复制一套资源处理路径。

具体例子：L3 enqueue(DATA) → L2 peek → AIV 计算 → L2 publish(DATA) → L3 read/release → STOP/drain。该往返不是 PR 首次提供；PR 使它通过模板事务和 Region 资源管理运行，并明确双端共享的布局、句柄与失败规则。

权威设计 W6 要求第一版有界 SPSC、有背压、不隐式扩容，MPMC 延后；P3④ / RA-11 还要求 BufferSliceArena 上的通用 publish/observe/wait。PR 正文明确只交内部模板与专用新 Region，不承诺既有 Buffer 绑定、跨节点、持久 queue 或公开模板 registry。第一阶段与最终设计方向一致，不能按 PR 子范围宣布父目标完成。

## 2. 方案与理由

模板只接收 depth、两条 payload arena 容量并计算布局。coordinator 在 Worker operation lease/control admission 内执行 `plan → resolve → materialize → bind → project → publish`：resolver 选端点与 backend，既有 Region 负责物化与物理寿命，模板校验 initiator/peer 身份和视图。一次性 bind token 由锁保护；bind 或 projection 失败关闭未发布实例，回收失败保留 unreclaimable 状态。queue.free 只关闭逻辑使用，不另建物理 owner。

一个 Region 承载两条 SPSC lane：L3→L2 接受 DATA/STOP，L2→L3 接受 DATA/ERROR。descriptor 容量固定、每方向 arena 独立；满时背压；input 可借出有限窗口并只回收连续完成前缀；output 一次一笔 reservation。句柄带归属检查，STOP 不妨碍排空输出，应用 ERROR 不等于基础设施 poison。超时可重试，首次失败保留，abort 通知失败仅附加诊断。SPSC 队列操作并不因此成为任意多线程可并发调用的接口。

native endpoint 接收注入的 RegionView 和 clock，不自行选平台。新的 SPSQ 绑定为精确 10 个 uint64，含 session/transaction identity；布局、版本、标量数或身份非法时拒绝。Python facade 保留 `Orchestrator.create_worker_chip_queue(...)`，旧 native L3Q2 decoder 删除，因此已有 L2 consumer 必须同步重编译。

发布顺序为 payload 可见 → descriptor fields → seq → tail 通知。借出的输出地址由实际写入者完成可见性义务；publish 不自动等待 AIV。示例的 `add_output(existing_tensor)` 登记 OUTPUT_EXISTING，`register_task_outputs` 将 producer 放进 TensorMap；`get_tensor_data` 调用 `wait_for_tensor_ready`，既查 owner 又查 OverlapMap 后等待 COMPLETED，然后 flush/publish。a2a3/a5 均核到此路径，示例未用绕开自动依赖的 manual scope。因而“external Tensor 没有 owner，所以必定不等待”的旧意见不成立；四条 GitHub review thread 当前均已 resolved。这里的顺序证据不替代任意 backend 的 cache-line 可见性证明。

## 1. 背景与问题（历史评审）

L3 host 与 L2 AICPU 已有双向队列：descriptor ring 引用每方向的 payload arena，head/tail counter 表示发布与回收，STOP 结束输入。此前 worker-chip 专用 Python 算法、native header 和 12-scalar L3Q2 binding 将高层队列与部署、物化代码耦合。W6 要求复用 Region 的资源与访问机制，首版只交付有界 SPSC；MPMC 并不属于这次验收。

具体用例是 L3 创建 queue、发送一块 DATA，L2 调 AIV 计算并返回 DATA，再由 L3 发送 STOP。该用例原来已经能运行，PR 的贡献是把它承载在内部模板事务和通用 endpoint 上，不能描述成首次具备 L3→L2 通信，也不能描述成 RA-11 全部退出条件已满足。

## 2. 方案与理由（历史评审）

Python coordinator 在 Worker operation lease 与 control admission 内执行 plan→resolve→materialize→bind→project→publish。plan 只描述布局；resolver 解释成员和 backend；RegionInstance 保持物理生命周期权威。bind 检查 slot 身份与两个独立 local view；plan 的一次性 token 防止重复绑定；project 未成功时由 coordinator 回收尚未发布的实例。回收失败保留 Worker 的不可回收错误，不把不确定资源当作成功释放。

兼容 facade 保留 create_worker_chip_queue 的调用形式，native 端接收精确 10 个 scalar 的 SPSQ 1.0 binding，含 session/transaction 身份。common endpoint 注入 RegionView 和单调时钟，不自行选择平台。双方镜像相同 little-endian descriptor、独立 arena 与 counter 布局；先完成 payload 可见性，再写 descriptor fields、seq，最后通知 tail。借出 native payload 指针的生产者负责设备侧可见性，publish 本身不能证明 AIV 已完成。

输入支持有限窗口：每个 handle 有归属，乱序 release 只推进已完成的连续前缀；输出最多一笔 active reservation。Python output handle 除字段外校验对象与 owner token。STOP 是输入终结，不阻止继续排空输出；ERROR 是应用消息，区别于基础设施 poison。计数器重构拒绝反向或超过 depth 的推进。失败先保留第一个错误，再尝试 abort 通知；native 诊断按 session/transaction 回到对应实例。

上述 DATA→AIV→DATA→STOP 用例现在复用同一模板与 Region 生命周期；只保留薄 facade，避免继续维护第二套队列算法。代价是明确切换 wire ABI：旧 12-scalar L2 编排必须重编译。PR 正文和用户文档已声明这项破坏性变更，不能要求暗中保留旧 decoder。
