## 0. 拓扑与层级模型对齐

用户给定拓扑正是仓库既有的 L0–L6 模型（`docs/hierarchical-level-runtime.md`）：

 | 用户术语 | 仓库层级 | 含义 | 实现成熟度 |
 | -------- | -------- | ---- | ---------- |
 | L2 = 一张昇腾卡 | L2 / CHIP | `ChipWorker`；片上 AICPU 调度 AIC/AIV，共享 device GM | 已实现（onboard） |
 | L3 = 一台机器管 16 卡 | L3 / HOST | `Worker(level=3)`：host 侧 Orchestrator+Scheduler+WorkerManager，fork 出 N 个 chip 子进程 | 已实现（onboard） |
 | L4 = 多机（本地+remote L3） | L4 / POD | `Worker(level=4)` + `add_mpirun_worker_group`；local fork、RemoteWorkerSpec 为已有其他入口 | mpirun + mailbox 派发与 A3 跨机 peer-TLOAD 已有；证据见通信方案 D.4 |

`Worker` 是 L3+ 通用类。**注意区分两个 level**：C++ hierarchical `_Worker.level_` 基本是标签（行为不按它分支）；但 **Python `Worker.level` 是公开语义分派键** —— `Worker.init()` / register / memory / run 按它分派，level 2 进入 `_init_level2`，level 3+ 进入 `_init_hierarchical`。
**L2 是分界**：L0–L2 在设备侧（片上自由调度），L3–L6 在 host/集群侧（DAG 编排 + fork/shm 或 socket 帧）。

4. **#711/#755/#803/#861/#866/#1090 均已 CLOSED-未合并，#1003 已 MERGED；#1105 Issue 已 CLOSED**。#803/#861/#755 的 host↔device/MPMC 需求轴没有随 PR 关闭而消失，但这些 PR 已不能当作在途实现；#1090 也只能作为 `TASK_RUNNING`/register-lane 的历史原型，不能作为当前 B3 基础。
5. **启动与建域分层**：主路径由 mpirun 拉起 L3；MPI 交换 Global CommDomain 描述符，A3 用 ACL/Fabric V2 建共享窗口。本地 HCCL `comm_init` 的文件式 rootInfo 不限制该跨机路径。选择 HCCL collective adapter 时另定义 opaque rootInfo 分发，不能当作现有 A3 RMA 的前置。
6. **"CPU 作对等 rank" 硬约束**：裸 HCCL 每 rank 必须 `aclrtSetDevice` 绑定一张 NPU —— **rank 是调用方分配的、绑定单卡的逻辑 communicator ID（≠ 物理 device ID；simpler 自身即用 `chip_idx` 作 rank、`device_ids[chip_idx]` 选设备）**；host CPU 进程不能作 rank；CANN 无 CUDA UVM/OpenCL SVM 式统一寻址。CPU、AICPU_TS、AIV、CCU 是**不同的通信引擎 / 资源视图（CommEngine）**，不是可互换的 rank。UB/URMA（Ascend 950/A5 级）扩大了对等直访能力，但**不改变"rank 绑定单卡"这一约束**——正确抽象是"一张 simpler 逻辑域 + capability-specific views"，而非把 host/AICPU/AIV 塞进同一个 `windowsIn[]`（详见 D.3 重写）。**区分 host-CPU（越 PCIe，只能 importer/copier）与片上 AICPU（本卡 GM/MMIO 可达，已是 L3↔L2 region 通道的对端）**。
7. **跨 run admission 按 main `fdcbdcc95021` 读取**：`begin_run()` 在 graph callback 前进入有界 pending FIFO；native slot lease 按可用角色稍后取得。FIFO head 可在构图期间执行，后继 prepare/early enqueue 受 backend、资源及顺序证明限定。设备清理的交接另受 ordered cleanup 约束；不能用 #1541 的旧 lease 时点描述当前实现。见 [L3+ 执行链](l3plus-design.md)。
8. **#1574（merged `87dce627`）只交付 B3a ownership seam**：native ABI 已有 `simpler_prepare_run` / `simpler_launch_run` / `simpler_poll_run` / `simpler_wait_run` / `simpler_finalize_run`；既有 `simpler_run` / `ChipWorker.run()` 是其 blocking composition。它没有增加第二个 mailbox frame、第二个并发 device execution 或 responsive EdgeChannel。
9. **A2/A3 SDMA 是“provider 编译、Worker capability 默认关”**：`Worker(..., enable_sdma=False)` 是默认；显式 `True` 才 provision worker-lifetime SDMA workspace/streams。独立 onboard ST 证明 opt-in 路径可用，不等于所有 Worker 常开 SDMA。
10. **A5 URMA 是“backend merged、capability/workspace gated”**：#1392 的 submit/CQ/completion 代码存在，但 device path 受 `PTO_URMA_SUPPORTED` capability gate，host overlay `SIMPLER_ENABLE_PTO_URMA_WORKSPACE` 又默认 OFF；当前基线不能把它写成可直接运行的 onboard 能力。
