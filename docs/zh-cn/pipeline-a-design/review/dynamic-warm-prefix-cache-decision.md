## 要解决什么

调用参数已由 #2432 放入 launch，普通 TMR run 仍会单独上传192 B执行配置前缀，其中包括绑核配置、函数表地址、arena地址和参数数量。对同一设备块，如果这些字节与上次发布完全相同，重复上传没有更新任何内容。

## 一个 PR 的改动

- 限 a2a3/a5 onboard TMR、已初始化的同一设备分配、capture查询成功且为NONE的现有 launch 路径。
- 每个持久参数块保留固定大小的host前缀副本和有效长度。仅比较已证明由host写入的[0,192)；命中则省去本run的一次192 B阻塞H2D。
- tensor描述和scalar仍每run由RTS复制。相同参数数量不代表参数内容相同，不缓存调用参数。
- 任意实际覆盖拷贝之前先使缓存失效；成功后才记录副本。部分失败后不得信任旧副本。重新分配、释放、abandon、首次初始化和descriptor回退都不继承有效缓存。
- 保留一次性snapshot消费、原始错误、NotStarted、无成功发布则不launch的合同。

## 必须落实的实现细节

比较与成功后固定数组复制都放在RuntimeLaunchImage::publish的回调内；回调中的source只在本次publish内有效。不能在publish返回后读取它（captured已销毁）。回调前将helper置Empty以保持重入拒绝，成功后再置Published。副本更新不分配内存、不抛异常。

256 B固定数组加4 B有效长度是每块的字段原始大小；双槽合计520 B原始字段，实际结构大小可能因对齐略增，PR以sizeof静态证据报告。只在字节完全相同时命中，不承诺某种工作负载必命中。

## 范围与代价

首次完整初始化、capture/未知查询回退、HBG、kernel/persistent、sim及现有准入/同步/槽位寿命不变。无设备布局变化，不改P4调度。增加每块约260 B host字段与一次最多192 B比较；未命中照常上传。命中减少一次拷贝调用和192 B传输；无延迟收益承诺。
