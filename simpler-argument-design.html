构造与接入 · Buffer → Tensor → TaskArgs → Worker

  1. 1 · 取得 Buffer分配 / 源侧 Buffer.wrap / 授权 import；确定存储身份与位置
  2. 2 · 建立 TensorTensor(buffer, shapes=..., dtype=...)；只建 view，不分配或复制
  3. 3 · 本次参数TaskArgs 保存 tag、transfer、scalar；不修改 Tensor
  4. 4 · 提交与校验Worker.submit 验证源登记、grant、范围、endpoint 与代际
  5. 5 · 内部接入复用 attachment、解析本地地址、保留使用；不改变 backing identity
  6. 6 · 完成与关闭按最后使用退出；借用内存的物理寿命仍由调用方保证

统一 COPY · 网络 → H2D

  1. 1 · 明确请求A.HOST → B.DEVICE；网络发送与当地 H2D 都须获授权
  2. 2 · 共同校验与绑定两端权限、完整路径、预算；保留源 H_A、中间 H_B、目的 D_B
  3. 3 · 网络复制源读取结束可释放本段源引用；send 返回不能放行 H2D
  4. 4 · 当地 H2D接收端 H_B 可用后才启动；H2D 不再读 H_B 后才回收中间存储
  5. 5 · Device 消费D_B 可见后有序启动；已有 D_B 的 identity 不变
  6. 6 · 最后使用与失败消费/回拷完成后退休；部分失败禁止后继，未知静止时保留资源

Program · 本地 L3 → L2

  1. 1 · 构造参数一个 Tensor 列表；TaskArgs 每项声明 NONE/H2D
  2. 2 · L3 接纳校验 identity、具体 chip、既有 grant 与调用方向、几何；登记使用与依赖
  3. 3 · 目标端解析HOST SHM 在 host prepare 映射；DEVICE 在所属 chip 解析
  4. 4 · 本次绑定HOST 留给 HBG；H2D 建 device 副本；DEVICE 借用
  5. 5 · 编排与 launchHBG 在 host 构图；TMR 在 device 编排；不隐式跨侧读
  6. 6 · 完成与退休双侧最后使用 + 必要 copyback 完成，释放本次保留

Kernel · 调用方设备资源 → 同一执行核心

  1. 1 · 提供参数调用方提供 DEVICE operands，host 控制值单独传入
  2. 2 · Host 准备权限/范围/环境校验；host 控制值显式快照；记录设备效果
  3. 3 · 执行绑定借用 caller DEVICE；simpler 管理内部 workspace；拒绝隐式 H2D
  4. 4 · Launchcaller 顺序 + 完整 device 发布；A3 两侧都纳入完成边界
  5. 5 · Replay 合同重复已捕获 device 效果；不会重新跑 host orchestration
  6. 6 · 生命周期submission / graph 保留资源；caller IO 所有权不转移

Remote · 值传输到另一机器

  1. 1 · 发送入口显式 HOST_INLINE：值快照；传输形式与 transfer 分开
  2. 2 · 网络传输校验 frame/session/version；不发送可供远端解引用的本地 VA
  3. 3 · 接收端 backing新 HOST Buffer、新 canonical identity；保留 dtype/几何/权限
  4. 4 · 当地参数绑定NONE → host 编排；H2D → Program device 副本
  5. 5 · 当地执行依赖满足后编排/launch；本次回拷完成后确认结果
  6. 6 · 回收receiver backing 按任务寿命回收；结果回传须走显式合同

Remote · 导入同一 backing

  1. 1 · Owner export原 identity + incarnation + owner-relative 范围 + 授权
  2. 2 · Target 选择机制判断 endpoint 关系和已实现 profile；不能仅看 Remote 标签
  3. 3 · 建 attachment同机 SHM 可映射；跨机器 peer 未实现则拒绝，不能自动 copy
  4. 4 · 新 Tensor 视图共享 backing；目标 grant、局部地址、范围单独登记
  5. 5 · 使用与依赖同 backing 统一 footprint；不同 import_id 不分裂 alias
  6. 6 · 关闭先关新使用资格；最后使用退出后 unmap，owner 最后回收

复制：两份存储

HOST backing H ── H2D ──▶ DEVICE backing D

目的 identity 不因重复复制而改变。后续写入不自动传播。

源码事实基线：main c605b03cad7be2a80700efbdf3bd00dbc79812a9。PR #2444 分支 1761d1304eec8b1ea7836d8d2f6812acbc5b2498 单独对照，不能当作主线。符号、差异及验证见 代码证据。HTML 阅读版 从本文和子文档生成。

1. 总体决定：一个公开 Tensor，一个公开 Buffer

L3+、Remote、L2 对用户统一为 Buffer + Tensor。 Buffer 表达存储身份、位置、容量与归属；Tensor 是该 Buffer 的几何视图；一次调用的 transfer 属于 TaskArgs 参数项。用户不需要先把 Tensor 转成另一种 ChipTensor，也不维护 HostControl / DeviceOperand 两份参数列表。

统一公开对象不要求把所有内部结构做成同一块内存：BufferDescriptor 是 Buffer 的可传输描述，已解析的地址和使用保留是本次绑定结果。现有 ChipTensor 可在迁移期保留为内部 ABI 编码，HBG/TMR 自己的调度 Tensor 也可保留；这些都不成为第二套公开资源模型。

用户：一个有序参数列表（Tensor + Scalar）
                     │
L3+ / Remote：Buffer 身份 + Tensor 几何 + 调用要求 + attachment 引用
                     │ 统一跨 endpoint 请求：NATIVE / MAP / COPY
                     │ 授权、依赖、backend adapter、目标端解析
L2 host prepare：本次参数绑定 + 使用保留 + Program IO 记录
                     │
HBG host 编排 / TMR device 编排 → KernelLaunch → 双侧完成 → IO 完成 → 退休

Remote 访问与 host/device 访问是同一种跨 endpoint 问题。 底层统一 source/target、权限、范围、复制或映射语义、完成与使用保留；网络、SHM、H2D/D2H 由具体 adapter 实现。Remote 关系与 HOST/DEVICE 位置正交，同一路径可以先网络复制再 H2D。

Buffer owner 继续负责物理分配与回收；目标 endpoint 负责 attachment；本次调用负责绑定与实际复制步骤。完整共用接口、双端能力判断、多段路径、完成与失败规则见 跨 endpoint 访问合同。不为 Remote 和 device 分别维护一套参数生命周期。

1.1 六个正交维度

维度 归属 确定含义 不能推导什么
backing 身份与 placement Buffer owner owner incarnation + buffer_id + generation；机器、owner endpoint、HOST/DEVICE local/remote 不是固定的 location 值
访问授权 既有 Buffer / import grant；映射授权归 mapping grant READ、WRITE、READWRITE；提交时与调用方向检查兼容 不新增逐 Tensor 权限字段；授权不保证平台可达或数据就绪
视图几何 Tensor dtype、shape、stride、相对 backing 的 byte_offset 不改变存储位置和 owner
本次参数搬运 TaskArgs 的 tensor 参数项 NONE、H2D；D2H 已有设计位置但当前拒绝 不塞进 AddressSpace 或 READ/WRITE
endpoint attachment 目标端 registry 实际 profile、目标环境代际、有效范围、权限、局部地址或复制通道 存在 copy 通道不等于存在直接地址
本次使用 TaskArgs / callable / 操作入口 INPUT/OUTPUT/INOUT、实际 host/device 消费、依赖与 completion 不因 NO_DEP 就免除权限、范围、寿命检查

AddressSpace 只保留 HOST / DEVICE。H2D 是独立字段，不保留 #2444 的 AddressSpace::HOST_TO_DEVICE。READ / WRITE 是访问权限；H2D / D2H 是搬运要求，两者不是同一个枚举。

1.2 对象关系与存储位置

对象 保存什么 保存在哪里 / 谁拥有
canonical backing record 不变身份、容量、物理位置、owner、backend、最大授权 分配方或外部注册方的 registry
Buffer handle 指向 backing 的有效 owner/grant 引用；公开关闭状态 用户持有；runtime 验证私有登记，不能相信可修改的公开字段
Tensor descriptor Buffer 的描述引用、几何、可选 attachment grant 引用 视图按值复制；所有层级使用同一公开类型
TaskArgs 参数项 Tensor 值、既有 tag、独立 transfer 请求 本次调用；同一 Tensor 可在不同参数项使用不同请求
attachment record backing 身份、目标 endpoint/context generation、profile、映射范围与地址、授权、使用计数 目标 endpoint；owner 另保留对应 backing lease
per-run binding endpoint 可用地址与范围、源/目的关联、IO 记录、使用保留；按需编码内部 ChipTensor 本次调用；不引入可重复 submit 的 PreparedCall
Scalar 固定类型解释下的值位模式 参数值快照；不借用 Python 标量对象或其容器

Buffer 的物理位置不因 host 映射而变成 HOST。本次绑定的地址必须另有该地址可在哪个访问域使用的含义。当前无跨侧映射时两者相同；未来映射实现不能继续把这两个事实混在一个字段里。

目标描述的字段归属如下（语义布局，不宣称二进制 ABI 已交付）：

BufferDescriptor = identity + backing_location + total_bytes + owner_access
                   + owner_route + backend/owner payload
Tensor           = buffer_ref + byte_offset + shape/stride/dtype
                   + optional attachment_grant_ref
TaskArgs entry   = Tensor value + existing direction/tag + transfer request
Attachment       = backing_identity + target EndpointIdentity/context_generation
                   + owner_range + granted_access + profile + local resolution
RunBinding       = 参数序号 → 原 Tensor + target address/span + access_space
                   + leases + IO actions
ChipTensor       = RunBinding 的内部 ABI 投影；不另设公开构造合同
CopyRecord       = 源/目的绑定 + 实际传输步骤 + 中间存储 + 本次完成/清理记录

不增加 Tensor.view_access 或 ChipTensor.access/effective_access。授权只来自既有 Buffer/import grant；本次所需读写来自 TaskArgs tag、callable signature 和实际 get/set/copy 操作。普通几何 view 沿用源授权；映射/import 的收窄权限保存在对应 grant，不在 Tensor 上复制成另一份可修改状态。没有跨侧映射时 attachment_grant_ref 为空。

绑定阶段检查所需读写是否为授予权限的子集；需要供 host get/set 继续检查的约束保存在本次 host 侧绑定记录，记录关联原 Buffer/grant 与调用方向。L3 materialize 不能丢掉这一关联，但不要求把权限再写进 ChipTensor POD。上述 access_space 只说明已解析地址的 HOST/DEVICE 访问域，不是 READ/WRITE 权限。L2 外部指针先包装成借用 Buffer，登记显式 endpoint、容量、位置和 caller lifetime 合同，再通过同一个 Tensor 入口提交。登记为同一个 Buffer 的视图共用身份；地址整数不作为稳定身份。外部重叠 allocation 不能靠重复包装自动识别 alias，调用方必须复用或明确关联同一登记。借用登记不接管 allocation，也不自动取得长期 map/graph 保活能力。

Buffer 的 owner_route 是 locator，不是身份；跨机器 endpoint 解析由 registry 提供 node/context 信息，不在 address_space 增加 REMOTE_HOST 等值。变长 transport payload 放既有封包区域，以受检查的 offset/index 引用；公开调用仍只有一份 Tensor 列表。

BufferDescriptor 的 canonical 部分与 attachment 的 transport payload 必须区分。不能把同一 backing 的两个导入地址、不同授权范围写成两个互相冲突的 canonical descriptor。现有 ImportRegistry 的“同身份、不同 descriptor 拒绝”保护保留；新增 attachment 表承接可变的端点事实。

1.3 地址在哪里，为什么还要解析

Buffer 的 backend 载荷按机制保存地址或定位信息：本地 DEVICE_MALLOC 可以携带 device VA，POSIX_SHM 保存可导入名称，Remote 保存 owner 路由或引用。统一 Buffer 不等于每份 Buffer 都有当前进程可解引用的 void *。

Tensor 通过 Buffer 引用定位存储，再加自己的 byte_offset 和几何。只有在实际消费 endpoint 验证身份、授权、范围及就绪条件后，绑定层才得到可用 base；Tensor 的起点为该绑定覆盖区中的对应地址。Remote copy-only profile 没有本地 direct 地址，不能解析成一个假指针。

当前代码已经有可复用路径：Worker._materialize_l2_args 在 L2 接收 TaskArgs<Tensor>，经 ImportRegistry 和 materialize_task_args 转成内部表示，再走 run_materialized。改造以此为共同入口，收拢低层 ChipWorker 的公开构造和借用包装，不重做另一套 materializer。

当前 Tensor 按值嵌入 BufferDescriptor，并不强持有 Python Buffer 对象。目标也不靠 wrapper 引用计数解决所有寿命：已接受调用取得使用保留；有效 owner/import/map handle 各有合同；普通 Tensor 副本不能阻止显式 close。先保留现有在飞 free 拒绝，再按 §6 收口延后物理回收。

1.4 正式构造入口与内部接入

正式入口固定为 Tensor(buffer, shapes=..., dtype=..., strides=..., byte_offset=...)。 Buffer 管存储；Tensor 构造器负责 dtype、几何和范围检查。构造 view 不分配、不复制、不搬运，不创建新 backing identity；位置来自 Buffer，transfer 只在 TaskArgs 参数项中。

  • simpler 分配的内存由现有 worker.create_buffer / worker.malloc 返回同一种 Buffer；外部本地存储通过 Buffer.wrap(address=..., nbytes=..., location=...) 登记，Remote 通过有授权的 export/import 取得同一种 Buffer。
  • location 表达源存储的 HOST/DEVICE 与所属 endpoint/context generation，不是当前消费者；单独一个 device ordinal 不足以覆盖跨进程、跨机器和 reset 后的新代际。这里规定语义，不假称已有这个完整 placement 构造器。
  • Buffer.wrap 在源侧建立有效登记，不自动向每个 Worker 注册。Worker 在 submit 中验证来源登记和授权，建立或复用自己的 attachment，解析地址并保留本次使用。用户不额外调用 register_buffer。
  • 同一 backing 在不同 Worker 上使用仍保留同一个 identity；目标地址、attachment 和 grant 可以不同。不能简单把现有方法移到 Buffer 类，再取消 Worker 的 live/provenance 检查。
  • Tensor 在逻辑上引用同一 backing 记录；内部可保存描述符/句柄，跨进程经 registry 解析，不要求保留 Python Buffer wrapper。有效性及已接受使用的保留由登记合同控制，不能只复制裸地址，也不能仅靠 wrapper 引用计数。
  • 外部借用不转移 allocation 所有权、不自动保活调用方 Python owner。调用方保证容量、真实位置、地址稳定和实际使用期间存活；异常不是完成证明，关闭描述符也不是 device fence。
  • 目标关闭语义：逻辑关闭拒绝新使用，已接受的使用按完成边界保留内部记录；这不自动延长外部物理分配寿命。现阶段在飞 free/release 继续拒绝，延后物理回收按 U4 交付。

迁移期 buffer.tensor(...) 仅转发到同一 Tensor 构造与检查，不维护另一套状态或权限规则。仓内公开用例迁移到 Tensor(buffer, ...) 后移除旧入口；外部兼容需求须明确记录，不默认永久保留两个等价接口。worker.borrow_device_buffer(...) 也不是最终公开入口，#2475 的实现状态与调整要求见 §6.1.2。

2. 访问能力怎么判断：一个入口，分层证明

复用当前 buffer_adapter_candidates、DefaultRegionAccessService、BufferCapability 的判断体系。扩展它们覆盖实际操作，不另做一个“看 location 就准许访问”的旁路。

3. L3+ 到 L2：参数和依赖如何流动

3.1 本地 L3+ 流程

  1. Worker.create_buffer / alloc_shared_tensor 建 HOST backing；alloc_child_tensor 建指定 chip 的 DEVICE backing。owner 登记不变 descriptor 与授权。
  2. 用户由 Buffer 建 Tensor；slice 只变几何。同一 Tensor 可以作为两个参数项传入：NONE 用于 HOST 编排，H2D 用于 Program device 绑定。
  3. TaskArgs 按既有顺序容纳所有 Tensor 和 Scalar；每个 tensor 参数项保存本次 transfer。L3 tag 定义依赖与使用方向，callable signature 定义 L2 读写；两者必须兼容，不能悄悄放宽。
  4. submit 校验 target、权限、几何，登记 backing 使用；生成依赖。HOST 来源有前驱时，读取/快照内容须在相应 producer 完成后进行。
  5. child 收到 Tensor 描述；不能把其中的 backend 地址载荷直接当成本地指针，ImportRegistry 在该 endpoint 验证并解析。HOST SHM 在 host prepare 映射；DEVICE 仅在授权 chip 解析为 device VA。
  6. materialize 生成本次绑定，参数项的 transfer 独立保留至 Program adapter 消费。授权来源及 attachment 关联留在 host 侧记录，由既有 tag/signature 检查所需读写；内部必要时编码为 ChipTensor。
  7. HBG host 编排或 TMR device 编排消费自己的合法绑定；提交内核；最后一个访问者及必要回拷完成后释放本次保留。

L3 的 TaskArgs 值复制主要复制描述与 scalar，不是把所有 HOST backing 内容变成调用瞬间的快照。共享 HOST 数据有真实 producer/consumer 依赖；提前 memcpy 会读到前驱旧值。Kernel 的 host 控制参数快照则在其显式 host 准备入口完成，返回后不再借用调用方 host 容器。当前 SimplerKernelInvocationHeader.host_copy_tensor_count 的接收合同仍要求为零：开放该入口时必须同一改动更新封包生产者、消费者与容量检查，不能只增加 Host tensor snapshot 工具。

3.2 分配者与中间结果不能混为一类

backing 来源 当前实际机制 统一方案中的回收责任
create_buffer HOST POSIX_SHM，用户显式释放 owner handle + 使用保留；Worker 管物理关闭
alloc_shared_tensor / orch.alloc HOST HeapRing / FORK_SHM，scope 和 consumer 引用管理 runtime 自动回收，不能当普通 malloc 手工 free
alloc_child_tensor / L2 malloc 指定 chip DEVICE_MALLOC chip allocator 负责物理 free，登记身份与实际 chip
CommDomain window VMM/window 生命周期归 domain 普通 Buffer.free 拒绝；domain teardown 负责

HeapRing 中间结果的 Python Buffer wrapper 活着不代表 slot 永不复用。派生 Tensor 只在 scope/依赖保留内有效；要跨 run 保存结果，使用显式持久 Buffer 并复制/写入，不能让返回 wrapper 自动提升分配寿命。没有可延长 ring allocation 寿命的 allocator 合同，就拒绝把它导出为长寿命 mapping 或捕获到长期 graph。

本地现有 OUTPUT 的分配时机不能从旧注释推断：reserve_outputs_and_slot 现在只 alloc(0, ...)；需要存储时先用显式分配入口。Remote 输出同样先 remote_malloc/import，HOST_INLINE 只有读权限、不能作 OUTPUT/INOUT，也不隐式回传修改后的值。输出返回通过显式远端结果 Buffer + copy_from。

D2H 不支持只限制参数的自动搬运标签，不删除显式 copy_from / remote_copy_from。

H2D 在此参数接口表示“为 HOST 参数建立 Program 管理的 device 绑定”。 它不是 copy 指令计数：INPUT 复制到 device；OUTPUT 不读取未初始化 host 内容，完成后回拷；INOUT 复制进去并回拷。回拷是 Program IO 合同，不是 DEVICE tensor 被 host get 直接读取。实际 copy-in/copy-out 动作放在本次 IO 记录，不能再从 H2D 一字推断所有动作。缺失方向时保留原 Program 的保守 INOUT；不把它改成只入不出。

这保留既有 Program 输入输出行为，也明确命名的限度：H2D 是参数绑定策略，单独 copy_to 才是严格单向复制操作。后续若希望 API 只表达单向复制，应迁移全部 Program IO 合同，不能只偷偷改变一个枚举解释。

H2D 交给编排后的参数是 DEVICE；不得由这个参数找回原 host 指针。两侧都要用时，用户明确传两个参数。可以是同一 HOST buffer 的两个参数视图，或两个独立 HOST / DEVICE buffer；两份内容一致性必须由调用方或显式复制关系保证。

3.4 用户接口：Tensor 是视图，TaskArgs 表达本次使用

以下展示选定的目标构造 API，尚未完整实现；TaskArgs 的 transfer 已由 #2454 交付，但独立 Buffer.wrap 与 Tensor(buffer, ...) 的完整登记/接入合同仍待实现，不增加新的参数容器。

h = worker.create_buffer(nbytes)          # HOST Buffer
x = Tensor(h, shapes=shape, dtype=dtype)    # 只有 Buffer 引用与几何
args.add_tensor(x, TensorArgType.INPUT, transfer=TensorTransfer.NONE)
args.add_tensor(x, TensorArgType.INPUT, transfer=TensorTransfer.H2D)

# 同一 x 不修改；两个参数分别得到 HOST 绑定与 Program DEVICE 副本。
device_buffer = Buffer.wrap(address=ptr, nbytes=capacity, location=device_location)
y = Tensor(device_buffer, shapes=shape, dtype=dtype)
args.add_tensor(y, TensorArgType.INOUT, transfer=TensorTransfer.NONE)

L2 直入通过源侧 Buffer.wrap 包装外部指针，再用 Tensor(buffer, ...) 和 args.add_tensor(...) 提交；Worker 在 submit 内完成目标接入。源登记不依附于某个消费者，目标接入必须保留现有 owner/provenance 检查。不要求用户构造 ChipTensor；现有 ChipTensor 调用由兼容适配器转换，移除前迁移公开示例与调用者。

transfer 不进入 Buffer 身份或 Tensor 几何，也不由建立 view 决定。 同一 Tensor 在不同调用中的使用互不修改。TaskArgs 内部按既有参数序号保存请求；不拆成 host/device 两组，设备 ABI 也不需要机械复制这份 host 侧请求。

兼容期，旧入口省略 transfer 时保留已定义的默认行为：Program HOST/H2D、DEVICE/NONE；显式 NONE 与省略必须可区分。旧 child_memory 只在兼容入口解释为位置，不能成为另一份持久状态。新例子必须明确传 transfer；转成规范参数项后，不允许下游或远端再次猜默认值。Kernel 入口仍拒绝 H2D，不能继承 Program 自动搬运责任。

HOST+NONE 的 get/set 权限按实际操作检查；readonly 不允许 set。HOST 控制值最终编码成 device metadata，不等于原 HOST tensor 被交给 device 读取。

3.5 几何和 alias 的约束

  • bounds 检查用可达字节范围与溢出保护；非空 tensor 的末尾由 offset、shape、stride、dtype 决定，不能只用 numel * element_size。
  • 目标模型允许空视图不解引用；rank、dtype、枚举、身份、transfer 仍检查，空视图可保留构造器生成的零 stride/null。当前 L3 validate_tensor 拒绝零 shape/stride、L2 可表达空 Tensor；迁移要统一这条规则及 codec，不能宣称现状两层已经一致。
  • 当前 H2D 的 t.nbytes() 分配/连续 memcpy 不能覆盖任意 stride。本轮支持契约明确拒绝非连续 H2D/managed copyback，保留原生 HOST/DEVICE 合法 strided view；用户先打包或使用显式复制。后续通用 strided copy 必须同时定义 scatter 回写与空洞保护。
  • 两个 HOST+H2D 参数若需要写入且范围重叠，独立副本会改变 alias 语义。本轮在全参数预检时拒绝这类重叠；只读复制可以独立。不得通过简单保留源 identity 假装 device 副本共享存储。
  • 本次 Program IO 记录源/目的的对应关系，L3 完成时间覆盖回拷。源 H 和副本 D 是不同 backing，依赖由复制边连接；同 backing 的 view 才共享 alias 身份。

4. Remote 进入同一模型，而不是第三种 Tensor

4.1 先区分两种“远端”

远端执行：将调用发到另一机器，由那里的 Worker 使用当地 HOST / DEVICE backing。跨 endpoint 数据访问：目标使用源 endpoint 管理的数据，可明确选择复制到目的或映射同一 backing。远端直接解引用只是其中的 MAP 情况；TCP 连接不等于 peer memory 可达。

当前 host_tcp 的 REMOTE_DEVICE owner entry 实际是 HOST POSIX_SHM。EXPORT_BUFFER/IMPORT_BUFFER 传 SHM 名称并在 importer open：它要求同一可访问 SHM namespace，不能作为跨机器共享内存证据。跨机器可用的传值路线是 inline/RPC copy 到目标 backing；不静默把 import 改成 copy。

4.2 五条 Remote 数据流

使用场景 统一流程 身份与生命周期
小 HOST 控制值传到远端 HOST_INLINE 值 → 接收端新 HOST Buffer → transfer=NONE → host 编排 新 backing、新 identity；内容在发送入口快照，接收端保留至消费结束
HOST 数据发远端跑 device inline 或显式 remote_copy_to → 远端 HOST Buffer → transfer=H2D → 当地 DEVICE 绑定 网络复制与 H2D 是两个独立步骤；两端 completion 不混用
已在远端的持久 HOST/DEVICE owner-issued reference → session registry 验证 → 当地解析 保留该 backing 的真实 identity/location；不重新声明成 HOST_INLINE
同机可共享 remote import export 原 identity/授权范围 → importer 建 HOST_SHM_MAP attachment → 新 Tensor view 同 backing，新 attachment；不从不同 shm name/地址生成新身份
真正跨机器 peer mapping 真 transport profile + target grant + coherence + retain 当前无相应实现的组合直接报不支持；显式 copy 是另一操作

HOST_INLINE 不默认代表“host-only”，也不默认代表“H2D”。载荷如何过网络与接收后如何绑定是两个字段；transfer 必须穿过 codec 和 _materialize_task_args，不能由接收端硬编码默认值。

4.3 Remote wire 与身份迁移

保留现有 RemoteBufferHandle / RemoteTensorRef 作为兼容门面；新的内部语义统一为 Buffer/Tensor/reference，不要求使用者立刻重写为另一套顶层 API。TaskArgs 仍只有一份用户参数列表；编码器按 tensor index 管理变长 transport 表，这是协议实现，不能让用户维护第二份角色 vector。

新 wire 必须明确携带：

  1. canonical backing identity，包括真正 owner incarnation；node/session/owner route 独立存放。不能继续仅把 worker_id 填进 owner nonce 来跨 session 识别 backing。
  2. backing location、容量、最大授权；import 的 grant_id/generation、允许访问的 owner-relative 范围与收窄权限。
  3. Tensor 几何，以及独立参数项中的 transfer、调用 tag；scalar 的位模式及类型解释合同。
  4. transport kind（inline、owner reference、import reference）与版本化 opaque payload；地址只由对应 endpoint 解码。
  5. endpoint/session generation 以及协议版本/feature 协商。不认识新字段/组合必须拒绝，不按旧默认静默执行。

owner 分配成功即生成 canonical identity，export/import 全程传递；导入不另造 backing 身份。HOST_INLINE 为新副本，必须每个独立值有独立身份；同一次调用中需要 alias 时显式复用同一传输 backing，不能碰巧靠相同 offset 关联。

所有 tensor offset 采用 owner backing 坐标。 attachment 另存覆盖区间 [begin,end) 和对应 local_base，解析公式为 local_base + (tensor.byte_offset - begin)。导入切片不能既缩小 Buffer 容量又保留原 identity、再把偏移减掉一次；这会混淆 descriptor、bounds 和依赖坐标。

4.4 依赖与授权不在网络边界丢失

统一 dependency key 为 canonical backing identity；entry 带视图 footprint。Remote 不再把 offset 放在 key 中。同一 backing 不同 import_id、host/device mapped 地址仍相互可见；复制生成的新 backing 由显式传输边连接。

本设计沿用现有 L3 run 内依赖推导，不新增跨独立 run 的全局依赖追踪器；外部 stream、跨 run 与应用级一致性由调用方有序化。NO_DEP 仅跳过依赖推导，不能跳过生命周期和权限。

保留现有 tag 语义：INPUT 查前驱，INOUT 查前驱并登记新写者，OUTPUT/OUTPUT_EXISTING 只登记写者。统一 identity/footprint 不自动补上所有 WAW/WAR 顺序：覆盖既有数据需使用相应 INOUT 或显式依赖，读后覆盖也要显式保证先前读者完成。不能把此方案误读成任意相交读写自动全序化。

Remote 发送端、接收端、L2 使用端都不能放宽权限。接收端不可把 READ import 重建为 READWRITE 参数，再寄希望于发送端检查；grant 必须跟着参数传到下一层。

5. 映射视图、释放与数据可见性

为 device tensor 建 host view：返回新 Tensor，不修改原 Tensor，不复制数据。 新视图引用原 backing 和目标 attachment，地址可不同；源 location 仍 DEVICE。完整接口与状态机见 映射合同。当前跨 host/device 的两个方向均拒绝。

5.1 统一释放目标与现状迁移

选定目标为逻辑关闭立即生效、物理回收延后。Remote 已有 slot/import refs 与 pending-free journal；本地当前 host release 拒绝在飞、device free 受 control admission 约束。它们现在还不是统一语义，必须先有保留记录再修改行为，不能直接删检查。

物理回收条件是：owner handle 已关闭，所有有效 mapping/import grant 已关闭，所有 accepted submission、copy、host 读取、event wait、graph 使用保留均结束。普通 Tensor descriptor 不是无期限保活 token；用户若释放 owner 后还想独立使用别名，须有显式有效 grant。

public Buffer.close 也须服从 owner registry，不能绕过 Worker 直接 unlink/free；底层物理 close 留作 owner 内部动作。DEVICE_MALLOC、POSIX_SHM、CommDomain window 仍由各自 allocator 物理释放，不能统一成一个 rtFree。

释放 RPC 失败或调用部分成功时，保留 cleanup journal 与相关引用，禁止地址/代际复用。只有已确认的 teardown 或释放完成能解除；网络超时不证明设备已不再访问。沿用现有“不确定资源保留到受控 teardown”的方向，不引入基于超时的分布式自动回收。

5.2 Host 数据、Pipeline A 和 capture

  • 外部 producer 的 HOST/DEVICE 数据由用户保证就绪；L3 已声明 producer 的依赖由 runtime 执行。prepare 可提前进行描述校验、资源规划；依赖未满足的内容读取不能提前。
  • kernel host-control 值在同步 host 准备入口完成快照，不能把用户 host vector 的生命周期交给异步任务。Program 大 tensor IO 可持有受管理 Buffer lease 至 DMA/copyback 完成；借用外部裸指针时需显式 caller lifetime 合同，不能靠 Python wrapper 引用保活 allocation。
  • HBG 一次 kernel 调用必须在 launch 前完成 host 决策；不得等待本次尚未 launch 的图产生 control value。动态决策放 device 或由上层拆调用。
  • 每个 A3 逻辑调用涉及 AICPU/AICore 两次 launch，回收按两侧实际最后使用和后续 IO 完成；单一 kernel task 结束不够。
  • capture 记录 host 准备产生的完整 device 效果及必要发布；replay 不调用 host orchestration。仅改变 HOST 控制值不能假定 replay 重算图。改变编排拓扑必须重建；已定义的参数更新只能更新允许的数据。
  • graph 持有引用与稳定地址；view 公开关闭不破坏此前 graph 已取得的保留。context reset 使旧 generation 失效，不能继续 replay。
  • MTP 的 KV cache、权重、持久 token 状态为显式 DEVICE IN/INOUT；host control 是显式 HOST 参数。一个 device scalar 若运行期变化仍是 Tensor，不把它当固定 Scalar 快照。

6.2 错误与资源副作用

全调用结构/组合/权限预检在 host 内容复制、DMA、KernelLaunch 前完成；已建立资源失败后有逆序回滚记录。上报包含 arg index、backing identity/generation、source location、target endpoint、operation、transfer/profile、拒绝原因，不输出 tensor 内容或私有 transport key。

Python 入口抛异常，C++ 返回现有错误状态，HBG/TMR 走现有 fatal 通路。LOG_ERROR 不是成功返回；不允许失败后返回正常零值或继续 launch。错误分类至少区分 INVALID_ARGUMENT、UNSUPPORTED_ACCESS、STALE_REFERENCE、PERMISSION_DENIED、OUT_OF_BOUNDS，最终映射到仓库现有可表达的错误码，不需要另建错误生命周期。

跨 endpoint 访问与复制：共同合同

更新：2026-09-27。状态：选定设计，尚未完整实现。本文落实 Tensor 统一设计，由 运行时原则 约束。源码事实仍使用 2026-09-24 核查的 main c605b03c，本次没有把旧证据重新标为最新主线。

1. 同一种问题，不同访问机制

Remote 和 DEVICE 都可能是消费者当前不能直接解引用的存储。统一抽象是 source backing → target endpoint 的访问请求；网络、H2D/D2H、同机共享内存、设备地址解析是不同机制。

                                一份 Tensor 参数列表
                                         │
             本地 Program / kernel / remote callable / 显式 copy 或 import
                                         │ 入口转换，不推断新授权
                             统一访问请求与合法性判断
                           ┌─────────────┼─────────────┐
                      NATIVE 消费     MAP 同一存储    COPY 到目的存储
                           │             │             │
                   已有本地 attachment   │     源/目的引用 + 复制动作记录
                           │             │             │
              backend adapter：local / SHM / H2D-D2H / remote transport
                           └─────────────┼─────────────┘
                             目标绑定 + 顺序 + 使用保留

公开对象始终是 Buffer 与 Tensor，正式 view 构造为 Tensor(buffer, ...)；源侧 Buffer 登记与目标 attachment 分离，目标 Worker 在 submit 内验证接入，同 backing 身份不随消费者改变。TaskArgs 参数项提供本次 transfer，绑定层把它翻译为下面的内部请求。BufferDescriptor 只负责传输存储描述，ChipTensor 可作为绑定结果的内部 ABI 编码。

这三个 operation 是内部请求语义，不是新增用户逐参数角色表，也不替换 AddressSpace / AccessMode。

位置拆成 node/endpoint 与 HOST/DEVICE；remote 是 source/target 关系。机器 B 的 DEVICE 同时具有“远端”和“device”属性。H2D 不隐含跨机器；一次显式跨机器复制可以包含 NETWORK → H2D 两段。

源 → 目的 确定的语义 机制例子 / 支持条件
A.HOST → A.DEVICE 复制 H2D；源读、目的写、device 顺序
A.DEVICE → A.HOST 复制 D2H；device producer 完成、host 可见
A.HOST → B.HOST 复制 网络传输；接收端完整提交后可读
A.HOST → B.DEVICE 复制 网络到 B.HOST，再当地 H2D；或经过验收的直接传输 profile
A.DEVICE → B.DEVICE 复制 已实现直接路径；否则明确已支持的 D2H → 网络 → H2D 组合；无完整路径就拒绝
A 的 backing → B 的映射视图 同一 backing 的别名 必须有可兑现的 mapping/import profile，不能自动换成上述复制

后两行规定合同，不宣称当前已有这些网络/peer 后端。当前 host_tcp 的 SHM import 要求共享 SHM namespace，仍不能跨机器充当映射。

2. 一个内部接口，两类结果

在现有 Buffer/endpoint 判断与运行绑定之间建立共同接口。名称是目标内部接口，非当前已存在的函数：

AccessRequest {
    operation: NATIVE | MAP | COPY
    source: Tensor reference + backing/grant identity
    target_endpoint: EndpointIdentity + device context generation
    destination: existing Tensor reference | explicit allocation request  // COPY only
    required_access: derived from existing tag/signature/operation
    source_range, destination_range, layout
    execution_scope: host operation | program invocation | kernel invocation
    capture_policy, ordering_context, budget
}

validate_access(request) -> ValidatedAccess | error
bind_access(validated)    -> BoundAccess | error
issue_copy(bound_copy)    -> per-operation completion state | error
retire_use(binding, completion_proof)

required_access 是内部从已有调用方向或 copy/map 操作导出的检查输入，不是新的用户参数，也不序列化为 ChipTensor.access。授予权限查既有 Buffer/import/mapping grant；需要延续到 host 访问点的约束保存在本次绑定记录。不增加独立 Tensor.view_access / ChipTensor.effective_access。

ValidatedAccess 只是本次请求的检查结果，不是可缓存或多次 submit 的 PreparedCall；静态检查不取得永久授权。bind_access 必须在 registry 保护下重验 generation/状态并取得使用引用，然后才可异步执行。异步间隔不能靠先前的一次校验跨过 free/unmap。

两类结果：

  • NATIVE/MAP 返回同一 backing 的目标 attachment、有效范围、权限和使用保留。NATIVE 只解析该消费合同允许的 native/same-side 导入，不暗中创建跨 HOST/DEVICE 映射；MAP 明确申请新 grant。
  • COPY 返回源/目的绑定、实际传输步骤、临时 buffer 记录和完成状态。COPY 不产生源 backing 的 direct-load 权限，复制通道不伪装成可解引用地址。

负责 allocator、remote session、device context 的既有 owner 不转移给共同接口。接口统一校验和资源记账，adapter 调用各自 owner 的原有分配、发送、RTS copy、查询和清理操作。不为跨 endpoint 传输新建一套全局 scheduler。

2.1 请求、backend profile、完成机制各司其职

层 必须处理 不应处理
入口转换 将已授权 API/参数合同翻译为 request 因检测到远端就偷偷发网络复制
共同判断 身份、精确 endpoint、范围、方向、产品策略、可用机制 用 Python 可达对象代替 allocation lifetime

每个 profile 必须明确：支持的 endpoint 关系、operation、layout、执行及可见性机制、是否能提供 device-side 等待、capture 能力，以及哪些完成证明可用于回收。仅在枚举中出现不算支持。

3. 多段复制的确定流程

以 A.HOST 的输入，经网络送到 B.DEVICE 为例：

H_A ── NetworkCopy ──▶ H_B ── H2D ──▶ D_B ── device consume
        │                 │                │
  SourceReadDone_A  DestinationReady_HB  DestinationReady_DB
                          │                │
                 H2D SourceReadDone_HB    consume Done
                          │                │
                  可回收内部 H_B       可退休本次 D_B 使用
  1. 入口确认网络发送与目标 device 绑定均获授权；校验整条路径、预算、权限、几何，未支持的一段在传输前失败。
  2. 绑定阶段取得源与目的引用，分配必要中间存储。先登记清理义务，再公开异步工作；不能只有裸指针列表。
  3. 等待源 producer；NetworkCopy 执行后，只有 DestinationReady_HB 才能启动读取 H_B 的 H2D。
  4. 只有 DestinationReady_DB 才能启动 device consumer。若后端不能形成合法等待边，则在既有 host 调度位置等完成再提交，不在 device kernel 中途回 host 补工作。
  5. H_B 最早在网络写与 H2D 读取均已结束后回收；本例两者顺序已建立，因此 H2D SourceReadDone 是最后一步。D_B 还要覆盖真正 device 消费及 Program 输出回拷。
  6. 网络 send 返回不等于目的可用。发送缓冲可以保留到 send API 定义的源读取完成；若没有更细证明，保守保留至整次复制已证明完成。

这些顺序约束不要求逐段 host 等待。 后端若提供合法的 stream/event 顺序和失败阻断，可以提前 enqueue 后继，让设备等待前驱。DestinationReady 限制实际消费开始，不限制 host 提前提交的时刻。只提供 host completion 的网络后端，由既有 host 调度在接收完成后提交下一段；不得用忙等 host ACK 的 device kernel 伪造 bridge。

提前排队还必须证明异步失败不会把不完整目的交给 consumer；单纯 record 一个 event 不自动具备成功门控。复用已有执行域错误/停止机制，未能证明该合同的 profile 不开放提前 enqueue，采用已证明安全的完成后提交路径。未确认静止的已排队任务继续保留资源。

直接网络→device 后端若将来可用，可以替换 COPY 内部步骤，前提是复制的范围、布局、授权、返回值、可见性与源/目的寿命合同不变。当前选择已验收路径；不因一次 RPC 失败就临时换路径重写目的。

3.1 三个完成事实，禁止合并成一个布尔值

事实 证明什么 允许的动作
SourceReadDone 该复制不再读取源 释放这一段的源使用引用；其他任务仍可能保留源
DestinationReady 该复制目的完整且对目标可见 触发依赖它的消费；不表示 consumer 已完成
OperationQuiescent 所有已发起步骤都不再访问资源 允许失败清理或最后退休；不等于操作成功

以上是逻辑事实，不要求三个新物理 event。同步 memcpy 可在成功返回时同时满足；RTS 异步 copy 由对应 stream 完成证明；网络 ACK 必须按 receiver 合同解释。原有 Pipeline A 的 run 完成不能替代尚未结束的复制证明，反之复制完成不能替代 AICPU/AICore 完成。

完成引用限定 endpoint/session/context generation 与本次 operation 标识。Backing generation 描述 allocation 代际，不随每次复制递增。不得用上次相同地址的完成记录放行本次数据更新。

3.2 预算与背压

每次路径绑定记录实际目的新分配 bytes、临时 HOST/pinned bytes、临时 DEVICE bytes、在飞 transport 数量，以及实际需要的 completion 对象。按 placement 归属计费，共用 backing 不重复计算物理字节。

预算不足在接纳前阻塞或明确拒绝，取决于外层既有 API 合同；不是依赖 RTS 队列提供 WouldBlock。资源绑定允许失败回滚，但任何一步 DMA/send 发生前须保证其后续必要存储已有保留。中间 buffer 不能因“已进入网络队列”就提早复用。

3.3 失败、取消和重试

状态至少区分未提交、部分提交、已证明完成、失败且已静止、失败但静止性未知。某一步失败后不提交后继消费；已提交写入无法回滚成“从未写过”。对已有目的 Tensor，相关范围标为本次结果不可用，不能继续沿用旧值的成功状态。

取消停止新的步骤，不撤销已经发出的 DMA/RPC；保留引用至 drain/静止证明。超时而无静止证明时保留 cleanup journal，拒绝复用相关资源。沿用现有 owner/session 故障处理，不新增“网络超时就释放 device buffer”的规则。

默认不透明重试已部分提交的写入。只有后端能以 operation id 去重或提供可证明的覆盖/顺序合同，才可在同一请求内重试。公开 free 的幂等性不能推导为任意 COPY 幂等。

4. 身份、视图和内容各自稳定

COPY 写入既有目的时保留目的 identity；申请独立副本才产生新 backing identity。 后续读写不会自动传播，host/device 两份内容的一致性靠显式复制与顺序。

MAP 保留源 backing identity，产生目标 attachment/grant；普通 Tensor view 保留 identity 并改变几何。Remote transport token、import_id、本地 VA 和 network sequence 都不替代 backing 身份。

同一 backing 的别名仍用 owner-relative footprint 判断；中间副本有独立身份。复制记录显式关联源/目的，不能为“看起来是同一个逻辑 Tensor”而给副本共用 alias key。底层复制原语不默许重叠源/目的；同 backing 的重叠 copy 当前拒绝，除非某 profile 明确实现并验收了对应语义。

复制范围还必须包含布局合同。当前不支持的 strided H2D/managed copyback 继续拒绝；网络携带 stride 不使下游 H2D 自动正确。所有步骤使用一致的数据布局解释，不能网络传完整 span、device 按 numel 分配然后保留旧 stride。

5. 与 Pipeline A、Kernel、Capture 的衔接

共同访问接口复用已有 run/stream 的依赖和退休位置。可以并行开发静态请求、拒绝规则、adapter 接口、wire 与保留记录；消费已合入完成机制时逐后端验收，不修改 Pipeline A 的 admission 或另建 runner。

Host prepare 只在数据依赖满足后读内容。可以提前验证 descriptor、选择机制和预留资源，但不能提前快照前驱未写好的数据。

统一 COPY 合同不扩大 Kernel 的资源职责：Program adapter 负责创建 IO buffer 和复制；kernel 执行核心只消费已合法绑定的数据和 simpler 内部执行资源。Metadata 发布仍属于 runtime 执行协议，不能以“Kernel 禁止用户 IO 搬运”禁止 metadata H2D。

Capture 要求每一条被捕获操作及其等待边都能由 device replay 完成。普通 host RPC、网络接收回调、Python host 调度不能因为被包装为 COPY 就变成可捕获 task。当前这类工作放在 capture 外，并在 graph 使用输入前显式证明目标可用；没有合法 bridge 就拒绝在 capture 中接入。

直接网络/device 集成若未来提供真正可捕获的后端，仍须单独验收 generation、图保活和每次 replay 的数据版本。Eager 支持不等于 capture 支持。

6. 实施与验收入口

统一设计 §6 给出唯一实施顺序；本页不另维护一套阶段状态。必须覆盖：

  • 同一套 COPY 合同用同步 fake、异步 device fake、异步 remote fake 验证；不能只测公共结构构造。
  • 延迟 receiver commit：send 已返回，consumer 仍不能执行；延迟 H2D：H_B 不得复用。
  • 复制到已存在的 D_B 两次：identity 不变，本次完成不能被第一次完成冒充。
  • 第二段失败/取消：前段写入不冒充整体成功；未知静止状态下源/中间/目的引用不丢。
  • MAP 请求不可降级 COPY；HOST+H2D 不单独授权跨机器传输；kernel 不因可用 adapter 就开始自动搬运用户 tensor。
  • 本机复制无需走网络，remote 控制协议不绕过权限；同一接口不增加无必要的 RPC 或全局锁。
  • SourceReadDone、DestinationReady、OperationQuiescent 可独立模拟，验证最后使用者再回收。
  • 普通网络路径 capture 拒绝；capture 外更新与 graph 消费必须有可验收的顺序。

Tensor 映射视图合同

更新：2026-09-27。本文是 Tensor 统一设计 的映射子合同。以下描述目标行为，当前跨 HOST/DEVICE mapping 均不开放。本地/Remote 释放的现状差异以主文 §5.1 为准，不把这里的保留语义冒充现有实现。

1. 映射视图独立建模，不归入搬运标签

之前只在表里写“跨侧映射拒绝”不够：那只说明支持状态，没有给出映射的对象模型。

Buffer：canonical identity / generation / backing location / granted access
  └─ Tensor：dtype / shape / stride / offset；可选 mapping 引用
       └─ endpoint attachment：访问端点 / adapter profile / local address / 有效范围 / 权限

映射视图是同一 backing 在目标 endpoint 的访问入口。存储位置仍归 Buffer；视图可访问的侧归 attachment。Host 与 device 即使指向同一 backing，也可以具有不同虚拟地址。 不定义 HOST_MAPPED_DEVICE 或 DEVICE_MAPPED_HOST 位置枚举，也不把 MAP 放进 H2D/D2H 的 transfer 枚举。 概念上可沿用已有 ImportRegistry / adapter / capability 体系；这不是声明当前所有跨侧 attachment 已存在。

来源 backing 目标访问域 方式 数据与身份 当前支持
HOST HOST 原地址或跨 host 进程共享映射 同一 backing，保留 identity 沿用已有 host backend 和权限检查
DEVICE DEVICE 本设备地址；已有 peer attachment 保留 backing identity，地址限于有效 endpoint 沿用已支持的 endpoint/peer 合同，不自动开放所有设备
HOST DEVICE H2D 复制绑定 独立 device allocation，独立内容；保留显式源/目的关系 Program 已有 IO 路径
DEVICE HOST 显式 copy_from 写入另一个 HOST backing 保留既有 copy API；自动 D2H 参数标签仍拒绝
HOST DEVICE 映射视图 同一 backing 的 device 访问入口；无独立 tensor 副本 暂不支持，LOG_ERROR 并返回失败
DEVICE HOST 映射视图 同一 backing 的 host 访问入口；无独立 tensor 副本 暂不支持，LOG_ERROR 并返回失败

跨 host 进程的 POSIX_SHM 映射不是 host/device 跨侧映射，不能连同 L3 参数传递一起禁掉。AICPU 在设备上执行编排时属于 device 访问域，不因其是 CPU 指令就归为 host。

复制形成副本，后续写入不会自动传播。映射视图访问同一 backing，但这仍不保证无数据竞争或缓存自动可见：未来开放时必须同时满足以下合同。

  • 别名：保留原 canonical identity 和视图范围；不能为映射伪造无关 buffer 身份，绕开 L3 依赖检查。COPY 的目标则是独立 backing。
  • 权限：map_view 的 access 请求只能收窄，结果保存在 mapping grant；调用方向与实际操作不得超出 Buffer/grant 和后端能力。Tensor 只引用 grant，不新增 view_access。
  • 地址：只有映射成功后得到的目标 endpoint 地址可用于该端点；不能直接转型源指针，也不能假定数值相同。
  • 就绪/可见性：producer 完成、必要的 cache/coherence 操作完成后才可读；映射成功本身不提供这些保证，也不允许并发冲突写入。
  • 寿命：有效 view、在飞使用者及 captured graph 的引用共同保活 backing 和 mapping；最后使用者退出前不能 unmap/free。Generation/context 改变使旧 attachment 失效。
  • 机制选择：一次参数绑定明确采用 copy 或 mapped attachment，不能按平台能力静默切换；普通几何 slice/view 不创建跨侧映射。

完整映射合同在下面确定；当前实现只走支持策略的拒绝分支，不执行 map/unmap、缓存同步或 replay 映射保活。开放映射时不修改 Buffer 位置含义或用户参数类别。

2. 确定的公开接口与对象语义

以下是目标接口合同，函数名和参数名据此统一；尚未实现的入口报不支持，而不是假装产生 view。

# Buffer 决定原始存储位置；Tensor 仍是唯一的 tensor 参数类型。
host_tensor = Tensor(host_buffer, shape=shape, dtype=dtype)
device_tensor = Tensor(device_buffer, shape=shape, dtype=dtype)

# 几何 view：同一 backing、同一 attachment；不会调用平台 map。
slice_tensor = tensor.view(...)  # 沿用各层现有几何 view 操作，不新增另一套布局算法

# 显式跨侧映射：返回的仍是 Tensor，附带已注册的 mapping 引用。
host_view = worker.map_view(device_tensor, target=host_endpoint, access=READ)
device_view = worker.map_view(host_tensor, target=device_endpoint, access=READ)

# 释放这次 map_view 获得的映射句柄；不是释放源 Buffer。
worker.unmap_view(host_view)

map_view 返回新的 Tensor 描述，不原地修改输入 Tensor，不分配新的 tensor 数据 backing。 原 device tensor 继续使用 device 原生地址；新 host view 使用映射引用在目标 host endpoint 解析地址。两者共享源 Buffer 的 canonical identity。映射关系直接引用 backing，不把原 Tensor wrapper 当作存储所有者，也不形成逐层 parent Tensor 保活链。

源 Buffer 的 allocation 控制记录（DEVICE backing）
  ├─ 原 device tensor：native 参数描述
  └─ 独立 mapping 句柄：持有 backing lease
       ├─ 新 host tensor view：参数描述 + mapping 引用
       └─ 已接收的任务/graph：独立使用引用

源必须有可验证的 backing 生命周期合同。simpler 自有 Buffer 使用其 allocation 控制记录；外部 allocation 必须提供能实际保活存储的 owner lease。仅有裸 device pointer、尺寸或一个 Tensor wrapper 不足以建立映射寿命；不能获得这个保证的 map_view 请求明确拒绝。此限制不改变无映射 kernel 参数原有的 caller-owned 寿命合同。

host_endpoint / device_endpoint 是已有 endpoint 身份及 context generation，不是裸 HOST/DEVICE 字符串：host 进程 A 的 VA 对进程 B 无效，device 0 的 VA 也不自动对 device 1 有效。

map_view 的确定语义：

  1. 输入必须是有效的、未附带跨侧 mapping 的 Tensor；它本身没有 transfer 属性。映射视图用于调用时，TaskArgs 参数项必须请求 NONE，不把 map 和自动搬运合并。目标须在另一侧；同侧切片、host 进程间导入和已支持的 device peer 使用原有路径，不经这个跨侧接口。
  2. 校验来源 identity/generation、请求范围、权限、endpoint 关系及支持策略。当前在此返回 UNSUPPORTED，不调用平台 mapping API，不返回占位 view。
  3. 支持后，由目标 endpoint 的管理者实际建立映射；成功返回前映射已建立。返回的是可路由的 mapping 引用，不把另一个进程的指针当作本进程可用地址。
  4. 输出 Tensor 保留原 BufferDescriptor、dtype/shape/stride/offset，附带 mapping 引用；权限由该引用指向的 grant 保存，不在 Tensor 新增权限字段。只改变访问入口，不改变原 Buffer、其他 Tensor 或用户数据。
  5. 不复制 tensor 内容，不等待尚未完成的 producer，不允许“map 不支持就自动 copy”。

需要两侧消费时，原 Tensor 与映射后的 Tensor 是两个显式参数；不在一个 Tensor 中暗藏可供 get/set 自动切换的 host/device 双指针。当前 map_view 不支持，所以仍需两个分别具有 HOST/DEVICE backing 的参数，或通过 Program H2D 建立独立副本。

3. 描述格式：声明与已解析地址分开

对象 必须携带的语义 不允许混入
BufferDescriptor canonical identity、原位置、backing 大小、所有者权限、已有 backend 描述 逐调用 transfer、某个消费者的映射地址
Tensor 视图 Buffer 描述引用、几何、可选 mapping 引用 本次 transfer、未经 endpoint 验证的直接寻址、第二份 host/device tensor 类型
TaskArgs 参数项 Tensor、调用方向/tag、本次 transfer 改写源 Buffer 位置或身份
Mapping 记录 owner-issued id/generation、源 Buffer identity/generation、目标 endpoint/context generation、profile、映射范围、授予权限、生命周期状态 与 backing 无关的新 allocation identity
endpoint 本地 attachment 平台映射句柄、本地 base、覆盖范围、实际能力、可见性规则、引用计数 跨 endpoint 复用的裸指针

所有公开层级传同一种 Tensor，实际消费 endpoint 解析地址。 同一个 mapping 引用可被合法的同目标参数重复使用；派生几何 view 共享它，不重新 map。传到错误 endpoint/context、使用旧 generation 或扩展范围/权限都拒绝。

L2 必须把“已解析地址的访问域”与“原 backing 的位置”在术语和实现上分开：例如 DEVICE backing 的合法 host mapping，L2 host 参数使用的是 HOST 可访问地址。源 backing 位置与身份保存在原 descriptor 和 binding/lease 中，不靠篡改 Buffer.address_space 通过检查。拟将 L2 这个意义明确命名为 access_space，仍使用 HOST/DEVICE 值域；它不是第二个物理位置。

一个逻辑 kernel 可能有 AICPU/AICore 多个实际消费者。目标 device attachment 必须覆盖这次调用所需的消费角色，满足共同 descriptor 的寻址合同；只证明某一个处理器能读不够。无法提供所需共享地址或可见性时拒绝该 profile，不能把一侧 VA 当作另一侧地址。

Wire 编码必须同时更新生产者、解析者和版本/能力校验。不借 reserved padding 静默塞字段；不序列化 STL 容器或 host ownership 指针；接收方不认识 mapping/transfer 时拒绝。映射引用验证和 backing 身份验证是两件事，二者都不能省。

4. 组合裁决：标签不能偷偷改变访问方式

参数形式 有效目标 结果

Native DEVICE + NONE 已授权 DEVICE endpoint 同侧/既有 peer 访问

5. 顺序与可见性合同

Mapping 是 live alias，不是 snapshot。它不让 host 读提前完成，也不让 device 在 HBG 构图中途先执行。

数据流 完整顺序
HOST 写 → DEVICE mapped read host 写完成 → backend 要求的写入发布/可见性动作 → 有序 device launch → device read
DEVICE 写 → HOST mapped read device 写完成及必要发布动作 → 覆盖 producer 的完成边界 → 调用方等待 → host 侧必要可见性动作 → host read
两侧可能写同一范围 调用方或已有显式 DAG 依赖建立互斥顺序；仅持有两个 view 不允许同时冲突访问

不额外创建全局跨 run tensor 冲突推断系统。L3 已声明的 DAG 依赖和 canonical identity 别名检查继续生效；外部调用方及跨 run 的未声明关系仍由调用方负责。

Backend profile 必须明确规定其 release/acquire 可见性动作：硬件保证一致时动作可为空，非一致时必须落到具体可执行的位置。Runtime 在已声明的准备/执行/完成边界做这些动作；不能在 host get 中偷加 stream wait 或 D2H。若无法保证某个写入方向的可见性，就不授予对应能力并返回不支持。不能以“地址已经映射成功”替代这份合同。

调用方承诺 host 读取前已经完成必要等待。Runtime 不可能仅凭裸指针自动证明外部 stream 的就绪性。HOST buffer 若可能被 device 写入，即使原 host 地址一直有效，仍须遵守这条顺序。

映射来源 HOST 存储须是可注册、寿命明确的 Buffer；不能把临时 host 值快照参数悄悄升级为可被 device 长期访问的 caller 容器。simpler 不取得 caller host 容器的所有权。

6. 所有权、关闭、失败

映射是独立的资源句柄，不是源 allocation 的所有权转移。跨进程建立映射时，负责该 endpoint 的 runtime 管理本地 mapping，调用方持有 owner-issued 句柄。

创建前：全量静态预检 → 支持/后端检查
创建失败：清理已取得的部分资源，返回错误，不公开 view
创建成功：ACTIVE（允许派生 view 和提交）
unmap_view：CLOSING（拒绝新的派生和提交；已经接收的使用者继续保活）
最后一个已接收使用者退出：实际 unmap → CLOSED
  • 原 Tensor descriptor 的销毁不结束 backing 或 mapping；host view 的寿命不依赖这个 wrapper。不得原地修改原 Tensor 的地址、位置或权限。
  • free/close 源 Buffer 结束的是源 owner 句柄，拒绝通过它新建 native 绑定或 map。已存在且仍 ACTIVE 的 mapping 句柄拥有独立 backing lease，可继续按其授权使用；物理 free 延迟到全部保留义务退出。
  • unmap_view 只结束对应 mapping 的公开授权，不释放原 Buffer owner。派生的 Tensor descriptor 即使还在，也不能据此重新取得新使用引用；过期引用必须报错。
  • 一个 map_view 调用获得一个显式句柄；对其 unmap 使该句柄派生的所有 Tensor view 不能用于新的提交。不能靠 Python 对象引用数量定义跨进程协议。
  • 内部可以复用同一物理 mapping，但每个公开句柄的关闭不能撤销另一个有效句柄的授权；复用键包含 backing generation、endpoint/context generation、profile、覆盖范围及权限兼容性。
  • 有效句柄、已接收的 host 准备、device submission、状态读取和 captured graph 都是保留义务。A3 要覆盖 AICPU/AICore 两侧实际使用期限。
  • 原 backing 在这些引用存续时不能物理释放；API 可以结束调用方的 owner 句柄并阻止新派生，但真正释放推迟到所有引用结束。外部借用存储仍要求外部所有者履行同样寿命合同。
  • 未 map 成功不产生可用句柄。若部分映射回滚失败，runtime 保留受隔离的清理记录，不返回成功，不遗失仍需处理的资源。
  • 正常 unmap 失败时保留原平台句柄与清理状态，拒绝新使用，允许已有清理路径重试；设备/context 状态不确认时不能再把地址投入复用。
  • generation/context 的有效性检查和取得使用引用必须作为一次受保护的操作；不能先检查 ACTIVE，解锁后再使用一个已被 unmap 的地址。

这些是映射支持必须遵守的语义，不要求当前拒绝映射的实现创建整套 mapping manager。

7. Capture/replay 合同

  1. map/unmap 是 capture 外的资源操作。Capture 开始前 view 必须已解析，地址和映射代际稳定；capture 内请求新映射直接报不支持。
  2. 图记录 device 可执行地址及完整设备顺序，并持有 backing + mapping 使用引用；原 Tensor wrapper 的 host 生命周期不被转移给图。
  3. 调用方 unmap 结束公开句柄，但图先前取得的引用继续有效，允许已有图 replay；真正 unmap 晚于图销毁和最后一次 replay 完成。新图不能从 CLOSING 句柄取得引用。
  4. Reset/context replacement 使旧代际图失效；不能用同值的新地址冒充旧 mapping。图 wrapper 在允许 replay 前校验执行域 generation。
  5. HOST backing 的 device mapped view 是 live 数据来源。连续 replay 读新内容仍要求 host 写与各次 device 读取有序；图拥有 mapping 不等于拥有数据快照。
  6. DEVICE backing 的 host mapped view 仅让 host prepare 能合法读当前值。Capture 仍不会重放 host get/set；依赖每次 device 结果重新构图的调用不能因此变成可 replay，必须放 device 控制或显式拆调用。
  7. Backend 所需可见性动作若不能纳入 capture/replay 的合法有序路径，该 profile 的 capture 能力为不支持；不能由 eager 能跑推断 capture 能跑。

8. 与 Remote 和现有 capability 的衔接

同机 host SHM import 与跨侧 map_view 共用 backing/grant/attachment 的内部模型；公开入口仍按用途区分。同机 SHM 不证明跨机器映射；peer device profile 在当前 DefaultRegionAccessService 中仍拒绝，不能将“沿用 peer 合同”写成已交付 peer 能力。

沿用 EndpointIdentity 的 session_instance_id / registry_epoch / endpoint_id，并在 attachment 登记目标 device context generation。Buffer 的 owner incarnation 和 endpoint session 身份各有作用，不能互相替代。

attachment 存 owner-relative 的覆盖范围，local_base 对应范围起点；Tensor offset 始终保留 owner 坐标。不同导入范围不能改写 canonical backing 大小。读取地址 = local_base + (tensor.byte_offset - attachment.begin)。

主线调查 docs/investigations/2026-09-hbg-per-run-host-view-rebuild.md 已否定逐 run 重建映射的性能假设。本设计的显式映射按 backing/endpoint/grant 生命周期保留，可复用物理 attachment；不把禁用隐式映射误称为平台无法映射，也不重新引入每调用 map/unmap。此性能结论不使当前产品支持策略自动放开。

9. 统一访问层中的 MAP 合同

map_view 与 remote_import 都转为 共同访问请求 的 MAP，返回同 backing 的目标 attachment/grant；平台 H2D/D2H 与网络复制则转为 COPY。MAP 不能用 COPY 返回一个“看起来相同”的 Tensor：两者后续写入是否共享、完成与寿命不同。

同 backing 的权限、identity、owner-relative 范围在多次导入中保持；目标地址和 transport token 属于 adapter。跨 host/device 映射当前仍拒绝，共同层的存在不扩大 profile 支持范围。

map_view(..., access=READ) 保留为建立映射授权的请求参数，remote import 的 access 参数同理；它们不构成每次提交需要重复填写的 Tensor 权限字段；内部 ChipTensor 也不新增该字段。

3. 需要纠正的理解

  1. 平台有 mapping hook ≠ 共享 capability service 已开放该 profile。 两条路径当前并不完全一致；新策略必须覆盖 HBG 旧 accessor 的旁路。
  2. Remote API 存在 ≠ 当前所有 backend 支持跨机器共享存储。 host_tcp 的 inline/copy 与其 SHM import 是不同机制。README/设计里的 HCOMM contract 不能当作对应 producer/materializer 已实现的证据。
  3. 同 backing 的多个 import ≠ 多个 backing。 canonical 信息、授权范围与 attachment 本地地址必须分开；具体非零 export offset 行为需用端到端用例钉住，本文不把静态审计当成已完成缺陷复现。
  4. 当前不同释放行为不能靠重命名统一。 Remote 的 deferred free 是可复用先例；本地必须新增/接通使用保留后才能改变 release_buffer 的拒绝行为。
  5. 现有 Program HOST 输出依靠 copyback。 参数模型迁移不能把 H2D 的名字解释成“去掉输出回拷”；也不能利用回拷保留旧 host get DEVICE 的隐式行为。
  6. 几何校验正确不保证搬运正确。 同一合法 strided Tensor 可以给原生消费者使用，但现有连续 H2D 算法不能因此宣称支持它。

Simpler Tensor 管理领域术语

存储与参数

Backing：一份实际存储，具有稳定身份、容量、所在位置和负责其物理释放的 owner。两个地址相同不代表同一 backing，两个地址不同也可能指向同一 backing。

Buffer：对 backing 的受管理引用，描述其身份、位置、容量和授权。它不是 Tensor 的形状，也不是调用参数的搬运要求。

Tensor：backing 上具有类型、形状、步长和偏移的视图。L3+、Remote、L2 对外使用同一种 Tensor；host/device 只是所引用 Buffer 的物理位置。Tensor 自身不保存某次调用的 transfer。正式构造为 Tensor(buffer, ...)，不分配或复制数据；buffer.tensor(...) 仅作迁移期兼容转发。 Avoid：将 HostTensor、DeviceTensor、RemoteTensor、ChipTensor 当成并列的公开资源模型。

BufferDescriptor：同一 Buffer 的可传输描述形式，不是第二种公开存储对象。按 backend 携带定位信息或受限地址，必须经消费 endpoint 验证才能使用。

ChipTensor：现有内部地址/几何 ABI；公开入口迁移期保留兼容适配，不继续扩充第二套用户构造合同。

本次绑定：Tensor 在实际 endpoint 的解析结果及使用保留、复制记录。解析地址的需要不构成另造公开 Tensor 的理由。

参数搬运要求：TaskArgs 参数项中，描述这次调用如何从源 Tensor 建立执行参数绑定的 transfer 请求。它不修改 Tensor 视图或源 backing 的物理位置；与同一参数项已有方向/tag 共同决定 IO 动作。

Scalar：按值传递的定型标量，其类型、位宽和位模式共同确定含义。设备上会变化的一个数仍可以是 Tensor。

访问与归属

Endpoint：一次访问实际发生的位置，包括所属机器、进程或设备执行环境。Remote 是两个 endpoint 的关系，不是第三种存储位置。

Attachment：某 endpoint 访问一份 backing 的已建立机制，包括可用范围与权限。可执行复制的 attachment 不一定提供可解引用地址。

映射视图：通过目标 endpoint 的有效映射访问原 backing 的新 Tensor 视图。它共享数据，不是数据副本，也不修改原 Tensor。

复制：把数据写入目的 backing 的操作。目的可以已经存在；为副本新分配存储时才产生新身份，后续写入不会自动互相传播。

使用保留：为已接受的访问、有效映射或可重放图保留 backing 和必要 attachment 的义务。它不等于数据已经就绪。

逻辑释放：结束一个公开句柄接纳新使用的资格。物理回收须等其余有效使用保留全部结束。

就绪：本次读取所依赖的写入已经完成并满足目标 endpoint 的可见性要求。地址可达、权限足够和生命周期有效都不能替代就绪。

跨 endpoint 访问：从一个执行位置使用另一执行位置管理的存储。跨机器与 host/device 访问共用这一概念，具体访问机制可以不同。

访问请求：调用方明确要求的消费、映射或复制行为，包含源、目标、范围与授权约束。它不因平台存在另一种机制就自动改变语义。

复制路径：为一次已授权复制连接源和目的的一个或多个传输步骤。网络复制与 H2D/D2H 可以出现在同一路径中。

源读取完成：某次复制已不再读取源数据的事实。它不代表目的数据已经可消费。

目的可用：本次复制的目的数据已经完整写入并满足目标消费者的可见性要求。它不代表资源的所有使用者都已结束。

访问授权与调用方向：访问授权说明 Buffer 或导入、映射允许的读写，调用方向说明本次调用所需读写。调用需要不得超出已获授权。
